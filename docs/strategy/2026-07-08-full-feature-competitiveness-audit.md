# 全功能竞争力审计(grill-with-docs 五轮·自主拍板,待逐项验证)

> **追踪机制**:本文档是 D1–D19 决策的**分析上下文层**(为什么这么拍);决策的单一索引与状态流转在 [DECISIONS.md](./DECISIONS.md)(待验证→已批准/已翻案);不可逆决策的 why 沉淀在 [docs/adr/](../adr/);排期落点在 [spec §八](./2026-07-07-development-strategy-design.md)。四层链条保证每个决策可从任一端追溯。
> 方法:延续廷议轮的四段式——**现状事实(代码核实)→ 竞争力诊断 → 业界对标 → 拍板(定位/优化方向/排期)**。用户授权自主分析、全按推荐拍板,**决策点 D1–D19 汇总于文末表格供逐项验证**。已在前四轮拍板过的功能(记忆宫殿/技能修撰/廷议/位面自进化/批红生态/harness 内容轨道等)只作汇总引用,不重烤。
> 判定分三档:**强化**(有新工作项)/ **维持**(已达标,明确不加东西)/ **联动**(不加新功能,与已排期功能打通)。"维持"不是偷懒——防过度建设与防功能荒废同样是审计的责任。

## A 组 · 入口与触达

### A1. 多入口 bot(飞书 / Telegram 助手模式)

- **现状**:5 入口同源落 `POST /api/edicts`;飞书 WS+webhook、卡片批红(`approval_card.py`,名场面技术底座)、助手模式 v2、多 Bot 实例;TG 多分片;`SessionAnchor` 统一会话锚。
- **诊断**:功能完备,真正价值没讲透——IM 入口不只是"提交任务的另一个口",它是**治理的移动端**(批红/通知/召廷议都发生在手机上)与**起居注的采集面**(对话语气/时段/追问模式全是画像信号)。
- **业界**:海外框架几乎不做 IM 入口(OpenClaw 11 通道抽象是个人项目);Coze 渠道发布是国内对标但无治理面。IM×治理的组合国内外都稀缺。
- **拍板(D1,强化)**:定位升为**「治理随身」**:迭代 5 的批红"驳回+指导"、一键召廷议必须移动端同权(飞书卡片上能做的=Web 上能做的);起居注(迭代 4)显式把 IM 对话信号列入采集面。不加新渠道(WhatsApp/Slack 等待社区 PR,窄门原则)。

### A2. 通政司 Notifier(通知)

- **现状**:channel_registry + feishu/email/dingtalk 渠道 + renderer;**已有 `DigestGenerator`**(daily/weekly 数据摘要:成本+memorial 统计);防抖(CoPaw 借鉴)。
- **诊断**:两个发现。①通知是异步平台的"脸",但现状所有事件一视同仁地推——"睡觉时它干活"的名场面里,**半夜什么该响、什么该攒到早上**没有产品答案,这直接漏在主叙事上。②迭代 7 的"实录馆"若从零建就是重复造轮子——DigestGenerator 已是数据底座,缺的只是 LLM 修撰成《实录》叙事体。
- **业界**:通知分级/免打扰是消费级产品常识,但 agent 平台普遍没做(Codex/Devin 都是全量推);chief-of-staff 类分级(skip/info/action)理念可借。
- **拍板(D2,强化)**:通政司加**通知三级制**——紧急(批红请求/预算触顶/急停:穿透免打扰即时推)、普通(任务完成:日间推)、低(统计/巡检:并入 digest)+ **免打扰时段**(默认夜间只留紧急级)。排期:迭代 5(它是"敢放手"名场面的产品细节)。**(D3,联动)**:迭代 7 实录馆表述修正为"基于既有 DigestGenerator 升级:数据摘要 → LLM 修撰《实录》叙事体",防重复建设。

### A3. Web 前端

- **现状**:17 页面,DAG 图/位面谱系树/晋升审批视图/批红台/成本报表/时间线俱全;`tsc` 零错但零测试(迭代 0 已排 vitest)。
- **诊断**:功能覆盖已超同类开源(多数 agent 框架无 UI 或仅 trace 查看器);短板不是缺页面,是**叙事对齐度**——宣发截图将来自这里,三个主叙事(敢放手/双引擎/组织新陈代谢)各需要一张"一眼懂"的界面。
- **业界**:LangSmith/Langfuse 的 trace UI 是"工程师调试审美";天枢的"朝堂审美"(批红台/谱系树)是差异化视觉资产,应放大而非趋同。
- **拍板(D4,强化-轻)**:不加新页面;宣发前(迭代 3.5–宣发窗口)对三视图做**叙事抛光**:批红台(敢放手)、位面谱系树(组织新陈代谢)、事件时间线(全程留痕),各以"能否截一张自解释的宣发图"为验收。Hooks UI 维持迭代 5 不变。

### A4. CLI

- **现状**:typer 全命令覆盖(edict/memorial/event/decree/universe...)。
- **诊断**:目标人群是终端重度用户,`pip install` 后的**第一条命令体验**=第一印象;现状装完后"怎么确认装好了/配置对不对"无一键答案。
- **业界**:zeroclaw `doctor`(结构化自检:配置/provider/连通性,Severity+可修复项)、`brew doctor` 心智;crush/Claude Code 的 TUI 精致但那是别人的主场。
- **拍板(D5,强化)**:**`tianshu doctor` 提前到迭代 1**(原在迭代 7 巡按族):检查 .env 完整性/LLM 连通性/DB 可写/端口占用,输出结构化诊断——soft launch 后新用户的第一条命令,装机体验的第一道保险。**(D6,维持)**:明确不做 TUI(不与 Claude Code 类工具竞争交互界面,进不做清单)。

## B 组 · 调度与规划

### B5. 钦天监 Scheduler(调度)

- **现状**:immediate/at/cron 三模式 + 并发去重(skip/allow)+ schedule_run 台账 + 孤儿 Sweeper(heartbeat 回收);NL 敕令(自然语言→调度,在 assistant_branch)。
- **诊断**:可靠性达标(multica 借鉴已收);真实短板是 cron 是"哑"的——定时任务不管值不值得跑都全量跑(每日竞品监控在无变化的日子照烧一遍 token)。
- **业界**:Inngest/Temporal 是可靠性维度(已达标);"条件调度"(cron 先跑廉价前置检查,有变化才全量执行)在 agent 平台无成熟对标,而它与成本治理叙事直接协同。
- **拍板(D7,强化-后置)**:**条件调度**(cron job 可配"前置哨兵":一次廉价检查(如 HEAD 请求/hash 对比)决定是否触发全量执行)列入 2027H1(P3 前),不挤 2026;命名归位:调度域隐喻定名**钦天监**(掌历法授时,贴切),进 glossary。**(D8,维持)**:NL 敕令、Sweeper、并发台账均达标,不动。

### B6. 内阁票拟 Planner(规划)

- **现状**:LLM 规划 → Plan(tasks + priority_order)→ `edict.plan_review=true` 时走 `plan.pending_review` 预审(票拟呈御览已实现)→ DAG 展开;passthrough 单任务兜底。
- **诊断**:票拟机制领先(市场 HITL 普遍无 plan 级审批),但两个缺口:①`plan_review` 是**手动逐 edict 开关**,高风险任务不会自动要求票拟——治理逻辑断了一环;②规划质量无反馈闭环(规划得好坏没人度量)。
- **业界**:OpenHands Planning Mode 2026-03 才 beta(天枢已有且更完整);LangGraph plan-and-execute 无审批位。领先位置应巩固。
- **拍板(D9,联动)**:票拟接入"大事慎决"生态——迭代 7 六科封驳的成本/时长预估**超阈值时自动置 `plan_review=true`**(六科出预估→内阁出票拟→用户批红,治理链闭环);重大 plan 可一键召廷议(复用迭代 5 廷议入口)。**(D10,联动)**:规划质量进 Evals(迭代 2):新增"plan 被 amend/重规划率"指标,喂京察。

### B7. DAG 引擎

- **现状**:Plan → 静态 `depends_on` 依赖图,节点独立 persona+memorial,并发执行+级联取消;节点可标注 executor(客卿,3.5 起)。
- **诊断**:会被质疑"为什么不做动态图(执行中生长)"——LangGraph 是图灵完备的图,看起来更强。但在天枢的治理语境下,**静态是特性**:图先于执行存在,票拟才有东西可审、六科才有东西可估、级联取消才有确定边界。动态图=计划不可预审,与治理叙事根本冲突;执行中的新需求已有归宿(orchestrator 外环迭代 + follow-up 机制)。
- **业界**:市场生产系统已收敛 orchestrator-worker(约 70%),swarm/动态 handoff 因成本与不可控退潮——静态 DAG + 外环恰是收敛点上的形态。
- **拍板(D11,维持+立 ADR)**:**明确拒绝动态图**,立 ADR-0009(deliberate no,防止未来贡献者"好心修复");DAG 本体不加功能。

### B8. 泳道 / WorkerPool / 级联取消 / 重试 / Checkpoint

- **现状**:双层背压(session/global)+ 有界重试 + 级联取消 + checkpoint 断点续跑——自带轻量 durable execution。
- **诊断**:工程达标且是差异化护堤(agent 框架普遍没有 workflow 引擎级语义);已知缺口(journal/replay,崩溃恢复不重放外部副作用)已在 P3 排期。
- **拍板(D12,维持)**:不加新功能;它的变现走内容轨道(《泳道与级联取消》已在候选队列)。

## C 组 · 治理与安全链

### C9. 都察院 Auditor(审计)

- **现状**:规则快筛 + LLM 深审两层,`review_policy` 四档(never/on_failure/on_flag/always),三态裁决驱动 memorial 状态机;审计意见喂太医诊断器。
- **诊断**:"敢放手"的支柱之一但**存在感低**——审计默默运行,用户只在出错时感知;规则集是代码内置的,用户无法表达"我的红线"(例如"涉及生产数据库的一律 flag")。
- **业界**:LLM-as-judge 已标配;deer-flow GuardrailProvider 是协议化可插拔思路;"用户可配审计规则"在开源 agent 平台罕见,且是治理开放性的直接证据。
- **拍板(D13,强化-nice)**:**审计规则 YAML 化**(用户在配置目录声明自定义规则:匹配条件→verdict,热加载)进迭代 7 nice 位;审计的可见性由实录馆(审计统计入《实录》)与 OTel(迭代 3)自然解决,不另做面板。

### C10. 太医诊断器

- **现状**:失败奏折/审计意见 → 演化域内代码假设(hypothesis)→ code_mutator 定向变异 → 自主提案(cron 05:30 + 手动 API)。
- **诊断**:独特资产(自进化的输入端,市场无对标),但**只服务代码层位面**——诊断出的问题若是"配置错了/凭证过期/依赖缺失"这类,根本不需要进化,直接告诉用户就行,现在这条路不存在。
- **业界**:SRE 界 AIOps 有"诊断→建议"模式;agent 平台无对标。
- **拍板(D14,强化-nice)**:太医开**双出口**——出口一:演化假设(已有);出口二:**「太医奏折」**(配置/凭证/环境类问题直接上奏折给用户,附建议修法)。与巡按(heartbeat 巡检)衔接:巡按发现异常→太医诊断→分流两出口。排期:迭代 7 nice(与巡按同族)。

### C11. 鸿胪寺(外网治理)+ MCP 客户端

- **现状**:EngineRegistry 热更新/凭证注入/SSRF 多层防护/host 白名单/滑动窗限流;MCP 客户端接外部工具。
- **诊断**:自研工具的网络治理达标;**真实边界问题**:MCP server 是独立进程,其内部网络行为鸿胪寺管不到——若宣发时说"网络能力全治理",一个 MCP 工具就能打脸。2026 年 MCP 安全(工具中毒/数据外带)恰是热点话题。
- **业界**:MCP 官方 roadmap 在补企业治理;市面 MCP gateway(如 LiteLLM proxy 的 MCP gateway)做集中管控。
- **拍板(D15,强化)**:诚实分级的 MCP 治理三件套进迭代 3(深防御同族):①MCP server **准入清单**(显式注册才可用,tier 标注);②MCP server 子进程 **clean-env**(复用迭代 3 产物,凭证不透传);③文档诚实声明治理边界("MCP server 进程内行为不在鸿胪寺管辖,准入即信任决策")。不做 MCP 流量代理(过度工程)。

### C12. 凭证托管 Secrets

- **现状核实**:**已是密文落库**——Fernet 认证加密(AES128-CBC+HMAC),主密钥 `TIANSHU_SECRET_MASTER_KEY`,前端响应不含密文;评估凭证隔离(TIANSHU_EVAL_LLM_*)。
- **诊断**:此前 plan 文档"凭证密文落库核查"项**已达标,降级为小核查**;与 multica secretbox 对照的唯一差距:无 key 轮换预留(multica 有 key-id 前缀字节)。
- **拍板(D16,强化-小)**:迭代 3 加**主密钥轮换脚本**(new key 重加密全表 + 双 key 过渡窗口),半天级工作量;master key 缺失时的报错语义核查(应显式报错而非静默)。

### C13. EventBus / 事件时间线

- **现状**:主链路事件解耦 + `edict_id` 全程落库时间线;审计留痕的地基。
- **拍板(D17,维持)**:达标;OTel 埋点(迭代 3)直接复用它做 span 映射,无新工作项。

### C14. 户部 Cost(成本治理)

- **现状与已拍板**:计量/熔断/归因已有;出厂预算护栏+成本透明(ADR-0003)、太仓命名(迭代 1)、记忆 ROI(迭代 4)、Evals/客卿预算闸——本轮无新增。
- **拍板(D18,维持)**:已在前四轮拍满,不再加。

### C15. 官员画像 Profile(persona 成长画像)

- **现状**:profile_synthesizer 按官员合成擅长领域/健康度/退化候选(PROFILE.md,规则聚合+LLM 两段);CancelledError 修复在迭代 0。
- **诊断**:与迭代 7 京察(persona 考核)是同一数据的两个视图——**京察若另建考核体系就是重复建设**。
- **业界**:无对标(agent 的"人事档案"是天枢独有心智)。
- **拍板(D19,联动)**:迭代 7 京察表述修正为"基于 PROFILE 数据的考核视图+处置动作(演化提案/致仕建议)",不另建指标体系;画像的"退化候选"直接作为京察降级预警输入。
