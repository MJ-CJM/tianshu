# 颁敕表单 UX 全链路分析与优化方案

> 触发:用户反馈「颁发新敕令的『更多设置』和『长程任务设置』参数很多,让人选花眼」。
> 交付:现状盘点 → 问题诊断 → 业界对标 → 优化方案 → 决策点。
> 状态:**Q1–Q6 已实现(v0.2.5,`feat/edict-form-ux`)**;用户「按推荐来」全批,
> Q7(平台级默认下沉全局设置)按推荐单开第二轮。

## 一、现状盘点:表单里到底有多少参数

代码落点:`web/src/components/edict/EdictForm.tsx`(主表单)+ `RuntimeConfigSection`
+ `AcceptanceConfigSection` + `policy/PolicyProfilePanel` + `NetworkCapabilitySection`。

盘点结果:**约 40 个可配置项**,其中**真正必填只有 1 个(目标)**,其余 39 个
后端全部有合理默认或可选。

### 主表单(始终可见,6 项)

| 字段 | 默认 | 说明 |
|---|---|---|
| 标题 | 空 | 可选 |
| **目标** | — | **唯一真正必填** |
| 执行模式(自动规划/直接指派) | 自动 | radio |
| 指派官员 | — | 仅直接指派时,条件必填 |
| 规划官员 | 空 | 仅自动+多阁臣时 |
| 计划预审 | 关 | 仅自动时 |

### 「更多设置」折叠面板(约 19 项)

- 主体 6:上下文、优先级(默认 normal)、审阅策略(默认 always)、执行器(默认
  native)、约束、输出格式。
- RuntimeConfigSection 6:超时(300)、最大迭代(20)、最大并发(1)、重试上限(0)、
  token 预算(无)、成本预算(无)。
- PolicyProfilePanel ~5:策略模板 + allowed_paths + allowed_bash_prefixes +
  tier_overrides + auto_approve_max_tier(**已有模板机制**)。
- NetworkCapabilitySection 2:api_request_hosts / write_hosts。

### 「长程任务设置」折叠面板(开启后约 13 项)

模板预设(4 按钮:分析/创作/编码/研究,**已有**)、执行剖面、最大外环(5)、
最小外环(1)、critic 严格度(lenient)、截止时间(时+分)、耗尽策略(escalate)、
critic 不可用策略(skip)、critic 官员(有默认选中)、同问题阈值(2)、L1 最大轮(2)、
L2 最大轮(1)、检查项列表(每项:名字/类型/命令或 rubric+阈值/超时)。

## 二、问题诊断:根源是「表单 = 后端配置镜像」

一句话:**这张表单是后端可配项的镜像,不是用户意图的入口**。开发者把
`EdictRuntime` / `AcceptanceCriteria` / `PolicyProfile` 的每一个字段都原样做成了
UI 控件——「配置暴露 = 能力暴露」的经典反模式。具体表现:

1. **必填/可选比例失衡**:40 个字段里只有 1 个必填。新用户面对一堵墙,不知道
   哪些非填不可、哪些可以不管。
2. **已有预设没起到「收纳」作用**:表单里已有三处好东西——长程 4 模板、策略
   模板、自然语言智能填充。但**预设是「填充」而非「模式」**:点了模板,字段被
   填上,但**全部字段仍平铺在下面**,用户还是看到 13 个长程字段。预设没有把
   细节收起来。
3. **专家概念下沉不足**:critic 官员 / 严格度 / 耗尽策略 / L1-L2 升级轮数 /
   同问题阈值 / 最小外环——这些是长任务外环的深度专家旋钮,99% 的用户既不懂
   也不需要碰,却和「目标」摆在同一个渐进披露层级里。
4. **分层错位**:人人关心的**成本预算**埋在 runtime 深处;而几乎没人会调的
   **L2 升级轮数**却和它同级平铺。重要性与可见性不匹配。
5. **默认值不可见**:超时、最大迭代等是 placeholder 空占位,用户不填时不知道
   系统会用什么值(300s?20 轮?),只能猜或去查文档。

### 认知负荷量化

- 首屏(未展开折叠)可见字段:约 6 个,尚可。
- 展开「更多设置」:再加 ~19 个。
- 展开「长程任务设置」并开启:再加 ~13 个。
- 全展开:**一屏约 40 个控件**——这是「选花眼」的直接来源。

## 三、业界对标(ai-example 同类产品实证)

读了 6 个同类产品的创建/输入表单,逐项:

| 产品 | 首屏字段 | 高级项处置 | 预设 | 默认可见 | NL 填充 |
|---|---|---|---|---|---|
| kimi 会话创建 | **1**(工作目录) | 全部延后到聊天里 | 当前/最近目录历史 | 默认目录高亮 | 无 |
| multica 建 Agent | 6(名称必填) | **默认折叠卡,折叠态显示预览+已选数量**;更隐蔽项完全不入表单,靠「复制模板」携带 | 复制已有 | 可见性/model/runtime 自动兜底 | 无 |
| kimi 聊天输入 | 1(textarea) | 配置外置到页脚,**全局持久化非逐条** | / 命令、@ 文件内联 | — | 无 |
| picoclaw | 1(textarea) | 无 | 无 | — | 无 |
| hermes | 1(富文本) | 外置到 ComposerControls | 启发式占位符 | — | @// 补全 |
| deer-flow | 1(textarea) | 模式选择器(Flash/Pro/Ultra 大卡)+ **条件披露**(reasoning-effort 仅模型支持时出现) | **意图芯片带 [topic] 可编辑槽** | 模式由模型能力自动推导 | **每轮生成后续问题芯片,点即回填** |

**跨项目共识**(6 条):①首屏极简——几乎都收敛为 1 个主输入,绝不铺大表单;
②渐进披露——高级项用折叠卡/action-menu,或干脆延后;③**预设代替逐字段**——
复制模板 / 意图槽 / 历史;④智能默认可见且自动推导;⑤**条件字段按相关性显隐**;
⑥**全局配置与单任务分离**(平台级参数持久化在全局,不逐任务填)。

**可落地到 Ant Design 的手法**:①35 项全进 `Collapse`,折叠标题显示已选摘要
(「Pro·重试 3·并发 4」);②`Segmented`/大卡做意图预设一键配一组;③`Form.initialValues`
给全部默认 + 每项标注「留空将用 X」;④`Form.Item dependencies` 条件渲染(critic
官员仅当需要、耗尽策略仅当长程);⑤顶部 NL 框「AI 帮我配置」回填整表;⑥token/
成本/并发/重试下沉到全局设置,创建表单只覆盖差异。

> 天枢自身已有三处对的东西(长程 4 模板、策略模板、NL 智能填充)——方案不是从零
> 造,而是把这些**升格**(填充→模式)并补齐业界共识里缺的两条:折叠摘要、全局
> 默认分离。

## 四、优化方案(推荐:意图驱动的三层渐进披露)

核心思路:**把表单从「配置项镜像」翻转成「意图入口」**。用户表达意图(填目标 /
选任务类型),系统配好参数;只有确需微调的专家才逐个字段调。三层:

### 第一层 · 极简默认(始终可见,约 3 项)

- **目标**(必填,大输入框)——唯一门槛;
- **智能填充**(自然语言→表单,已有,提升为默认可见的一行「描述你想做什么,自动
  填表」);
- **一排「任务类型」预设卡片**(见第二层)。

新用户体验:填个目标 → 提交,或点一张预设卡 → 提交。**首屏从 ~6 控件降到 3**。

### 第二层 · 意图预设卡片(替代逐字段填)

把现有的「长程 4 模板」从埋在长程面板里的填充按钮,**升格为整个表单的意图选择**。
候选卡片(每张 = 一键配好一整套参数并**收起细节**):

| 预设卡 | 一键配好 | 面向 |
|---|---|---|
| ⚡ 快速执行 | 单任务/自研引擎/不长程(现默认) | 大多数即时任务 |
| 📊 分析报告 | 长程 foreground / 外环 5 / critic 都察院 | 调研、汇总 |
| 💻 编码任务 | 长程 checkpointed / 检查项(lint/test)/ 截止 1h | 写代码 |
| 🔬 长程研究 | 长程 background / 外环 15 / 严格 critic | 深度长任务 |
| 🤝 客卿模式 | 派 Claude Code + 影子快照 | 反向驱动外部 agent |

选中卡片后,下方只显示**该预设的 2-3 项关键摘要 + 一个「微调」入口**,不平铺全部
字段。预设从「填充」变成「模式」——真正起到收纳作用。

### 第三层 · 专家模式(默认收起,一个开关)

一个「专家模式」开关(或「微调」入口)。打开才显示当前生效的全部细粒度字段,
按语义**重新分组**(而非现在的 runtime/policy/network/长程混排):

- **执行**:执行模式、执行器、超时、最大迭代、并发、重试;
- **预算**:成本预算、token 预算(⭐ 提到显眼处);
- **权限**:策略模板、路径/命令白名单、网络白名单;
- **验收**(长程):外环、critic、严格度、耗尽策略、检查项;
- **专家旋钮**(最深):L1/L2 升级轮数、同问题阈值、min_outer——只在这里出现。

### 横切改进(不分层,普适)

1. **默认值可见化**:placeholder 从空占位改为显示当前默认(如「默认 300 秒」),
   用户不填也知道会用什么(业界共识④)。
2. **重要性 ⇄ 可见性对齐**:成本预算、审阅策略提到第二层显眼处;L2 轮数等下沉到
   专家旋钮。
3. **智能填充强化**:NL 智能填充应能推断预设卡(说「帮我写个脚本并跑测试」→ 自动
   选「编码任务」预设)——对标 deer-flow 意图芯片(业界共识③)。
4. **折叠标题显示已选摘要**(业界共识②,multica 实证):专家模式/预设收起时,标题
   显示当前关键配置(如「客卿·成本上限 ¥5·长程 15 轮」),不用展开就知道配了啥。
5. **条件字段按相关性显隐**(业界共识⑤):critic 官员仅当验收需要时渲染、耗尽策略
   仅当开长程时出现——`Form.Item dependencies` 实现,减少无关字段。
6. **平台级默认下沉到全局设置**(业界共识⑥,deer-flow/kimi 实证):超时/最大迭代/
   并发/重试/token 预算这些**平台级偏好**,应在「系统管理」设一次全局默认(天枢已有
   `GlobalConfigTab` 可承接),创建表单**只在需要偏离时覆盖**——而非每道敕令重填。

### 认知负荷改善量化

| 场景 | 现状可见控件 | 方案后 |
|---|---|---|
| 新用户提交简单任务 | ~6(需理解执行模式/审阅) | **1**(只填目标) |
| 常见任务(选预设) | 展开长程 ~19 才能配 | **点 1 张卡** |
| 全展开(专家) | ~40 平铺混排 | 分 5 组、按需展开 |

## 六、诚实边界

- 本方案是**纯 UX 重构**,不改执行语义——同样的敕令,新旧表单产出的 `EdictCreateRequest`
  等价(只是获得它的路径更短)。风险低。
- 「意图预设卡」的参数组合需要几轮真实使用校准(现有 4 模板的数值是初始猜测);
  上线后按反馈调,不追求一次到位。
- Q7(全局默认下沉)是**最有价值但也最伤筋动骨**的一项(动 AgentConfig + 两处 UI),
  可独立于前 6 项后置;若想快出效果,先做 Q1-Q6 的纯前端分层,Q7 单开一轮。
