## 二、核心竞争力定性

**一句话:天枢是市场上唯一把「自进化」放进完整治理框架的 agent 平台——自进化敢上生产,因为每一步都被评估、审计、可回滚。**

三根支柱(按市场稀缺度,证据见 plan 文档 §2.1):

1. **双层自进化闭环**(独此一家):行为+代码两层平行位面,沙箱配对评估 → fitness 门控 → 审计留痕 → 可回滚晋升。同类(微软 SkillOpt,2026-06)只做 skill 层;代码层自改+部署级回滚无商业对标。
2. **治理组合拳**(组合稀缺):工具分级 + 策略管线 + 人工批红 + 双层审计 + 成本熔断归因,全程事件留痕;立法趋势(EU AI Act、加州 SB 53)正把治理变成合规卖点。
3. **长任务分级自治**(无产品化对标):验收契约驱动的 L0–L3 升级阶梯;市场 HITL 普遍是单级开关。

其余重资产的角色分层([ADR-0006](../adr/0006-heavy-assets-narrative-roles.md)):**记忆宫殿升入第二幕**(与进化组成双引擎——记忆感知,进化固化);**官员协作并进自进化叙事**(打「组织新陈代谢」牌,不打 multi-agent 红海牌,会诊/DAG 作"敢放手"技术背书);**harness/loop 走技术内容轨道**(每迭代一篇深度文);DAG/泳道/多入口仍为护堤,不进宣发主叙事。

## 三、发展主轴(四原则)

1. **加深不稀释**:一切排期围绕"让治理×自进化的故事更硬"取舍——Evals 给自进化补证据,起居注给自进化补方向(贴合用户),深防御给治理补底线,MCP server 与客卿给生态补双向接口。
2. **两段式发布**:soft launch 倒逼工程卫生;正式宣发带完整叙事(双语 README + 演示 + 架构博文,HN/V2EX/掘金)。
3. **细粒度特性流**:main 常绿,CI 护航,commit 图持续活跃本身即开源信号。
4. **明确不做**(全量见 plan 文档不做清单):computer use 自研、A2A(2026)、AG-UI、自研 LLM 重试框架(用 litellm.Router)、OpenFeature SDK(自研 flag 表)、E2B(macOS 不可行)、microVM、Temporal 默认、立即 PG/K8s、swarm 多 agent。

## 四、客卿执行器(新增设计 A)

**概念**:外部 coding agent(Claude Code / Codex,后续可扩)作为受朝廷节制的「客卿」——天枢保留全部治理面(规划/批红/审计/预算/成本归因/记忆沉淀),执行面成为可插拔 backend。**自研引擎仍是默认执行器**。

**与既有决策的关系**:2026-07-02 multica 评估排除的是"纯控制平面、自己不执行"的定位;客卿是"自执行引擎 + 可选外部执行器",定位无让渡。配合 MCP server 化(外部 agent 驱动天枢),构成双向互操作:*Claude Code 可以给天枢下旨;天枢也可以派 Claude Code 出工——两个方向都在治理框架内。*

**v1(迭代 3.5,MVP,~1.5 周)**:
- 新 executor backend:Edict/DAG 节点可标注 `executor: keqing:<agent>`;适配层走 headless CLI(Claude Code `claude -p --output-format stream-json`、Codex `codex exec`),适配器注册表复用鸿胪寺 EngineRegistry 模式(可插拔,OpenClaw/Hermes 等后排)。
- 治理集成四件套:独立 worktree 工作区隔离;clean-env 凭证不透传(依赖迭代 3 深防御产物,排序天然成立);预算熔断(解析 stream-json usage 归因成本);产出照常走 memorial → 审计 → 批红管线。
- 与位面演化联动:重编码变体生成可委派客卿,回收进三关门禁(plan 文档 P2-H 伏笔兑现)。
- 参考实现:deer-flow `tools/builtins/invoke_acp_agent_tool.py`(ACP 委派 + 独立只读工作区)。

**v2(v0.4 之后,2027 初与 A2A 一起评估)**:ACP 深度集成(双向流式、外部 agent 权限请求实时桥接到天枢批红)、外部 agent 作为会商"客座专家"。

## 五、起居注·用户画像(新增设计 B)

**概念**:现有 `profile_synthesizer` 是 per-persona 官员成长画像("官员擅长什么");**用户维度**目前仅有 memorial 显式 `feedback_score`。起居注补上"主人习惯什么、喜欢什么"的用户画像层,并把它接进自进化闭环——fitness 从"客观绩效"升级为"主人满意度",自进化的方向贴合真实使用者。隐喻:起居注即史官记录皇帝言行之册。

**信号源(全部已落库,零新增采集面)**:Decree 批红行为(approve/reject/amend + comment + grant_scope 模式)、Memorial 的 runtime_override/acceptance_override(follow-up 修正 = 用户嫌哪里不对)、feedback_score、Edict 提交模式(任务域/时段/频率)、SessionRules 显式规则。

**v1(迭代 4,画像层)**:
- 与"后台史官"共用蒸馏管线(史官蒸馏执行知识,起居注蒸馏用户习惯,同 cron 同机制);
- 产出 `USER_PROFILE.md`(Markdown 真相源,与记忆宫殿同构)+ 偏好三元组写入时序 KG(valid_from/valid_to,偏好漂移可表达、过时偏好可 invalidate);
- PromptBuilder 注入:官员开工前可见主人偏好——不等进化,立即贴合。

**v2(迭代 6,接进化)**:
- 行为层变异 prompt 注入用户画像(变异方向贴合用户);
- fitness 的 feedback 维扩展隐式满意度(批红通过率 / amend 率 / follow-up 修正率),不再只依赖显式打分;
- 配对评估集按用户常见任务域加权采样(进化优化的是主人的真实工作负载)。

**边界原则**:画像只影响**变异方向与评估加权**,不绕过门禁——晋升唯一门禁仍是配对沙箱评估,防画像过拟合短期行为。v1 按单主人假设(个人生产力场景);多用户画像隔离(按 user_id 分 wing)留到多租户需求出现。

## 六、明制透镜功能补全(新增设计 C)

以明朝制度为透镜系统扫描功能空缺。已核实**票拟预审已存在**(`edict.plan_review` → `plan.pending_review` → 批准后执行),不重复建。诚实分级:A 类是真功能缺口,B 类只是既有规划的命名归位(不加工期),C 类远期。

### A 类·真缺口(迭代 7「制度补全」交付)

1. **司礼监·代批**(must,依赖起居注画像):学习用户批红习惯,对低风险 decree 自动代批,解 HITL 最大痛点(审批疲劳)。**防"宦官专权"四道闸**:只代批策略允许的低风险类(tier 低/成本低/历史同类通过率高)、每笔留痕(`actor="silijian"` 的 Decree,事后可撤)、用户可随时一键收回批红权(接入急停)、代批准确率进京察考核。与迭代 5 的 approve_for_session 衔接:那是会话级白名单,司礼监是跨会话学习型代批。
2. **六科给事中·封驳**(must):诏令提交时预检——风险分级 + 基于记忆宫殿历史相似任务的**成本/时长预估**,不合规可"封还"(拒收并说明理由);zeroclaw gateway 入站防护(body 上限/幂等键)一并归此。
3. **实录馆·自动汇编**(must):周期(周/月)把 edict/成本/审计/演化数据 LLM 修撰成《实录》报告,经通政司推送;工程量小、演示效果好。
4. **巡按御史·主动巡检**(nice):heartbeat 驱动定期巡查(系统健康/任务积压/成本异常/记忆过期),异常主动上奏——zeroclaw heartbeat + doctor 借鉴项的落位。
5. **京察·persona 考核**(nice):周期考核报告(成功率/成本/审计通过率/代批准确率),不合格官员触发演化提案或"致仕"建议——Phase 3.12 官员绩效评估的制度化,与位面演化联动。

### B 类·命名归位(不加工期,增强叙事一致性)

- **锦衣卫** = 迭代 3 运行时安全监察的统称(出站脱敏/注入护栏/循环检测/分级急停);
- **科举** = 迭代 6 技能/persona 准入评测门禁的统称(SKILL.md 安装管线 + 三关门禁);
- **太仓** = 迭代 1 持久预算池/配额记账的命名。

### C 类·远期(2027+,不排期)

**翰林院·储才**(persona 生命周期:孵化/观政/转正/致仕,与京察联动)、**宗人府**(多主人/多租户隔离,需求出现时)、**驿传**(P3 分布式消息的隐喻归位)、**国子监**(技能内部培养沙箱)。
