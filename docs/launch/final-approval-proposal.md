## 最终方案：六入口、统一任务工作台、实验能力分区可见

一级导航按办公场景分为六个入口，御书房统一承载任务，实验与试行能力集中在天工院：

| 入口 | 用户目标 | 首屏只放什么 |
|---|---|---|
| 中枢 | 知道系统是否正常、哪里需要处理 | 当前执行中、未归档敕令、待裁决总数、累计证据束（含归档）、独特能力 |
| 御书房 | 新建、查看和管理全部工作，并处理需要人决定的事项 | 全部敕令、颁发敕令、钦天监、都察院 |
| 朝堂 | 管理百官并开展多方会商与协同决策 | 吏部、廷议、内阁 |
| 百司 | 管理知识记忆、外部联络与消息通知 | 翰林院、鸿胪寺、通政司 |
| 天工院〔实验〕 | 查看和试用仍在探索的差异化能力 | 演化司〔实验〕、诸界台〔实验〕、考功司〔试行〕、客卿馆〔实验〕 |
| 内府 | 管理运行环境、权限会话与成本预算 | 藏兵阁、权印司、户部账房 |

御书房默认显示全部状态，不再把“待裁决”误作整个办公空间。立即、单次定时、周期、
长程、对话和客卿等类型使用可叠加标签；状态筛选用于缩窄结果，执行进度以最新奏折和
持久裁决事实为准。旧 `/edicts` 地址兼容跳转到御书房，不维护第二套任务列表。

正式办公能力按场景分别进入朝堂与百司；前沿能力集中在天工院，并在入口上直接显示
成熟度。内府沿用藏兵阁、权印司、户部账房三个名称，不增加第三层菜单。

不再保留“有路由但默认找不到”的页面。Skills、工具、MCP、Provider、插件和紧急停止
继续在内府的藏兵阁中可达。“全部功能可发现”不等于把每个内部模块都做成一级入口。

## 成熟度标签

所有能力使用统一、可读的成熟度标签，不能只靠颜色表达：

| 标签 | 含义 | 页面行为 |
|---|---|---|
| 稳定（有限边界） | 当前正式支持范围内可依赖 | 正常提供操作，同时写明单机、可信本地等边界 |
| Beta | 主路径可用，交互或契约仍可能调整 | 可操作，说明可能变化的部分 |
| 实验 | 有真实页面、API 或运行结果，但保证尚不完整 | 可进入、可试用；页首固定显示“能做什么 / 不能做什么” |
| 暂未开放 | 只有设计、占位或安全条件尚未满足 | 可展示路线和原因，不提供会固定失败的按钮 |

当前分层如下：

| 分层 | 能力 |
|---|---|
| 稳定（有限边界） | 普通/长程/定时任务、裁决、Planner/DAG/Auditor、证据、成本、记忆、人格、Skills 只读目录 |
| Beta | 会诊、评测、插件 manifest 目录 |
| 实验 | 自进化、Skill 候选学习、平行位面/代码变体、客卿 |
| 暂未开放 | 自动 Skill 学习、插件安装/激活、位面运行时切换/自动晋升、客卿凭证网关、remote/open stdio MCP |

考功司仍属于 Beta 支持层级，古典中文导航使用更贴合语境的“试行”标签；插件 manifest
目录继续显示 Beta，不因导航命名而改变能力保证。

实验能力必须保留真实价值，但不伪造完成度：

- 自进化：展示候选、Gate、分流、回滚和停用原因；未启用时说明条件，不再只显示
  “暂无数据”；
- 平行位面：支持创建、分支、diff、评估、归档与恢复；明确不支持从 Web 切换或晋升
  运行时；
- 客卿：展示 Claude Code、Codex、Pi、OpenCode 状态、能力、隔离和治理默认；Git
  工作区准备成功时可强制运行前恢复点，但仍没有可靠事前动作拦截或 Provider 侧硬成本上限；
- 评测：展示真实评测集、运行、分数、失败分布和历史差异；没有数据时给出真实 CLI
  启动方式；
- 插件：展示 manifest 与能力声明，不提供安装、加载或激活。

## 中枢统计语义与刷新

中枢用四张主指标卡解释治理态势，而不是把“未结案”统一显示成“正在执行”：

1. **当前执行中**：只统计非终态运行实例；运行已经完成但仍可继续批示的任务不计入；
2. **未归档敕令**：统计当前可见且尚未归档的任务，并显示“待后续指令 / 已撤回”分项；
3. **待裁决总数**：统计尚未解决的持久裁决；
4. **累计证据束（含归档）**：统计可见任务历次生成的证据束，任务归档不回减累计数。

因此，“御书房有 6 条未归档敕令、中枢当前执行中为 0”是可解释的正常状态，不是同步
失败。普通主体的四项指标和摘要列表都按本人过滤；带 `admin` scope 的管理员统一读取
全局范围，不允许同一个快照混用本人和全局口径。

中枢在页面位于前台期间每 5 秒重拉权威快照作为兜底；相关执行、裁决、审计和长程任务
WebSocket 事件会让快照立即失效并重拉。页面转入后台后停止轮询，回到前台后恢复；两条
刷新路径只改善时效，不改变统计口径或数据真相源。

## 中枢如何体现竞争力

中枢总览已增加一块紧凑的“独特能力”区域，没有增加新的配置表单：

1. 长程治理（稳定）：检查点、暂停/继续、恢复、裁决和证据；
2. 自进化（实验）：候选、Gate、分流与回滚；
3. 平行位面（实验）：变体、diff、评测与推荐；
4. 客卿（实验）：治理外部 Coding Agent。

每张卡只显示成熟度、当前状态、一句话价值和“查看”入口。这样首次进入即可理解天枢
和普通任务面板的差异，但创建任务仍是最短路径。

其中自进化卡的状态读取控制中心权威快照中的 `evolution_status`，由
`EvolutionCenterQueryService` 的真实状态投影为“未启用 / 已启用 / 降级”，不是前端
写死的演示状态。

## 新建任务

首屏按下面的顺序展示：

1. 确认任务类型：快速执行（默认）/ 分析报告 / 编码任务 / 长程研究，后三类使用深度执行；
2. 可选填写标题，再写清目标；
3. 选择执行时间：立即 / 单次 / 重复。

预算、验收、权限、网络、重试等参数放进“高级设置”，默认折叠。深度任务自动使用
可检查点执行，不再要求用户理解 `foreground/checkpointed/background` 三套内部 profile。

四张任务类型卡只负责给出合理默认值，用户仍可在高级设置里调整。调度规则保持简单：

| 任务类型 | 立即 | 单次定时 | 重复 |
|---|---:|---:|---:|
| 普通任务 | 支持 | 支持 | 支持 |
| 深度任务 | 支持 | 支持 | 不支持 |

选择深度任务后，重复选项禁用并直接解释原因；后端各层继续 fail closed，不能靠隐藏按钮
代替校验。

## 任务详情

创建成功后直接进入该任务详情，不回到列表。详情按用户判断顺序展示：

1. 当前状态和下一步；
2. 进度、计划与输出；
3. 暂停 / 继续 / 运行中补充要求；
4. 需要用户处理的裁决；
5. 成本、证据和审计；
6. 专家调试信息（默认折叠）。

错误、空数据、无权限、服务不可用和未知地址都显示真实状态，不用示例数据或空白页兜底。

## 定时任务

定时任务页只保留用户常用操作：编辑时间、暂停、恢复、立即运行、取消和查看运行历史。
时区使用用户本地 IANA 时区并显示；misfire 默认只补最近一次。`run-now` 不修改原计划。

## 权限与实验能力

- 可信本地仍是默认正式边界；
- `secure-remote` 普通用户只看到自己的任务，管理员才有全局审计、Worker、记忆和平台配置；
- Skills 合并成一个只读目录，只保留详情和 Pin；Persona 外部导入只预览检测到的 Skill，
  不安装或激活；候选治理完成前不展示直接编辑、删除或归档；
- 插件只展示 manifest，不提供安装或激活；
- 自进化、平行位面、评测和客卿分别在“天工院 → 演化司 / 诸界台 / 考功司 / 客卿馆”
  中可见，并统一显示“实验”或“试行”成熟度；
- Universes / Code variant 只允许快照、提案、评估与归档，不展示固定失败的切换/晋升；
- remote/open stdio MCP 默认关闭；
- Keqing 标为实验，凭据由用户本机自行管理；未安装或默认关闭不影响页面可发现；
- 既有 Git 历史公开前须另行选择清洁快照，或完成已删除第三方包 publishable key 的
  轮换/撤销、历史重写和复扫；
- official container、PyPI/GHCR、签名和发布不在本次产品审批内。

## 审批结论与剩余 Gate

用户已批准最终六入口方案。当前实现冻结中枢、御书房、朝堂、百司、天工院、内府，
保留统一御书房任务工作台、天工院成熟度标签和中枢“独特能力”区域。选择该方案的
理由是：

- 普通用户只需理解“任务、时间、是否深度”；
- 长程与定时规则在界面和后端一致，不产生隐藏组合；
- 真实实验能力全部可发现，能够直接体现天枢的自进化、平行评估和外部 Agent 治理；
- 成熟度和能力边界在入口与页面同时呈现，不把“可看到”误写成“生产可依赖”；
- 独特能力有统一入口，但不会干扰任务黄金路径。

剩余 Gate 是用户视觉/交互审批；即使该 Gate 通过，仍需另行授权发布范围和发布动作。
