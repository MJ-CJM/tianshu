# 深度技术文 #1:治理 × 自进化,一个 AI 执行平台的架构取舍

> 内容轨道(ADR-0006)第一篇。宣发随 v0.3.0 发。目标读者:已在用 Claude Code
> 的独立开发者/效率极客。基调:讲清楚**为什么这么设计**,不吹功能。

## 一句话

Claude Code 是你在场时的刀,天枢是你不在场时的衙门——一个既**治理得住**、又
**能自己变好**的异步 AI 执行平台。这篇讲这两件事在架构上怎么共存。

## 一、为什么是"异步 + 事件链",而不是又一个对话 agent

对话式 agent(问一句答一句)解决的是"我在场、我盯着"的场景。但真正费人的是
**我不在场**时的活:每天把关注仓库的 PR 汇成日报、盯着某个长任务迭代到达标、
半夜跑批。这些活的共同点是**长周期 + 需要被信任**。

天枢的主链路是一条事件链:

```
下旨 Edict → 排期 Scheduler → 规划 Planner → 执行 → 审计 Auditor → 通知
```

每个里程碑事件(`edict.submitted` → … → `audit.completed`)带 `edict_id` 落库,
成为可复盘的时间线。子系统内部仍是直调(事件只解耦主链路里程碑,不搞
"全事件驱动"的过度设计)。这样任务流转全程可追踪、可干预、可复盘——**信任的
前提是可观测**。

## 二、治理:让"敢放手"成立的四道闸 + 一层运行时防御

自主性越强,失控代价越大。天枢的治理不是一个开关,是分层的:

- **决策层**:工具分级(tier)+ 策略管线 + 人工批红(手机上点准)+ 会话规则。
- **运行时层(锦衣卫)**:工具真正执行的最后一公里——出站脱敏(外发前抹
  secret)、bash 命令**分段**风险分级(堵 `git log; rm -rf /` 这种白名单前缀
  绕过)、子进程 clean-env(secret 不经环境变量泄漏)、分级急停(全停/掐网/
  冻结工具,一键刹车)。
- **放手四保险**:预算熔断、手机批红、影子快照一键回滚、出厂预算护栏。

其中**影子快照**值得单说:天枢派出去的执行器会改文件,但天枢**无权**碰你的
`.git`(你可能有正经版本历史)。方案是独立 GIT_DIR——快照仓的 `.git` 放在工作区
之外,用 `git --git-dir=<shadow> --work-tree=<work>` 操作,工作区里根本不出现
`.git`。回滚用 `read-tree` + `checkout-index` + `clean` 让工作区**精确**匹配快照
(连快照之后新增的文件都删干净——`checkout -- .` 做不到这点)。

## 三、自进化:怎么"证明"变好了

自进化最容易翻车的地方是"改完自我感觉良好,实际变差了"。天枢的答案是**配对
沙箱评估 + fitness 门控**:

- 行为配置(乃至代码)被捕获成可分支、可切换、可回滚的**位面(universe)**;
- 候选位面在**隔离沙箱**里回放历史任务,与冠军基线**同集配对**打分;
- 只有 fitness 严格提升(margin 判在配对差上)才晋升——这和微软 SkillOpt 的
  validation-gated 思路同构,但天枢动的不止 skill,还有行为和代码。

关键设计选择:**自进化默认关**。行为层达阈值(如一周 20 个审计通过的 memorial)
由系统主动上一道「臣请开启自我演化」的奏折,请你解锁——功能开关变成剧情事件,
既是留存钩子,又治理自洽(演化这种大事必须人点头)。

而"证明变好了"本身也产品化了:`tianshu evals run` 把配对沙箱评估泛化为**平台级
回归评测**,一条命令沙箱回放历史任务、与同集上次运行比 delta。配一套 17 类失败
分类学(借鉴 multica 的 taskfailure),每个失败自动归因、分布可查。

## 四、双向互操作:借势 Claude Code,不与之为敌

天枢定位「Claude Code 的上级机关」,靠两座桥支撑:

- **MCP server**:天枢是个 MCP server(`POST /mcp`),Claude Code 能给它下旨、查
  状态、读结果——Claude Code 命令天枢。
- **客卿执行器**:反过来,天枢能派 Claude Code/Codex 出工。执行面成为可插拔
  backend(自研引擎仍是默认),但**治理面不让渡**——客卿在隔离工作区跑、用它
  自己的凭证(clean-env 不透传天枢 secrets)、成本按 stream-json 归因并受预算
  熔断、产出照走审计→批红管线。

两个方向都在治理框架内。这不是"又一个 multi-agent 编排",是"一个把外部 agent
纳入治理的上级机关"。

## 五、明制隐喻:外壳与本体

天枢用明代六部官制作隐喻(内阁规划/兵部执行/都察院审计……)。有人会问:这是
不是"一群 AI"的营销皮?诚实说:**权限矩阵是本体,六部是同一个模型在不同权限约束
下的分工**——约束是真的,模型不必是多个。"一群"的真实含义是:多任务并发(真)+
多角色治理(真)+ 客卿外部 agent(真)。隐喻让复杂治理好记,但落到代码是清晰
解耦的模块——[隐喻对照表](metaphor-map.md)一一列出了每个宫廷词对应的工程实体。

## 尾声

治理和自进化,单拎出来都不稀缺。稀缺的是**交叉带**:一个既治理得住、又能安全
自进化的平台。天枢押的就是这条交叉带。
