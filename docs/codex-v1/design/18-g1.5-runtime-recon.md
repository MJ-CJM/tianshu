# G1.5 Slice B/C read-only reconnaissance

Snapshot: 2026-07-12, `/Users/chenjiamin/tiangong/tianshu`. This reconnaissance did not edit runtime code or run builds/tests. The only file created is this report. The checkout is concurrently dirty with the in-progress G1.4b3 governed-apply work (notably `app.py`, `gateway/auth.py`, `workspace_service.py`, migrations, REST/CLI tests), so Slice B must not start until G1.4b3 is committed and reviewed.

## Executive result

The smallest safe implementation order is:

1. Finish Slice A resource catalog/overlay and G1.4b3 final API first.
2. Add the explicit demo dispatch contract and its zero-network unit/integration RED tests.
3. Replace the current mutating/leaky Doctor implementation with a versioned, deterministic report.
4. Add readiness as a pure assessment plus narrow lifecycle properties; then update local/Web consumers.
5. Add one process-launching exact-wheel black-box test, with all orchestration kept inside the test (no new runtime launcher/script).

Three current blockers are concrete:

- Demo is absent. `TianshuSettings` has no `startup_profile`; `LLMClient.chat()` and `chat_stream()` call LiteLLM directly; the active DB configuration can override environment defaults.
- Doctor is not read-only and is not safe to serialize. `_check_db()` creates directories and a probe file; `_check_api_key()` emits the first six key characters; raw paths/exceptions are printed; there is no JSON/version/check id contract.
- `/health/ready` is already anonymously allowed by `SecurityBoundaryMiddleware._public_route()`, but no route exists. `/health`, `/health/live`, local startup, CLI health, and Web health currently only prove a constant `{"status":"ok"}`.

## Existing surface and exact symbols

### Provider/common dispatch

- `src/tianshu/llm.py`
  - `LLMResponse` is the common response shape.
  - `LLMClient.chat()` -> `_chat_once()` -> `litellm.acompletion()` (or injected LiteLLM Router).
  - `LLMClient.chat_stream()` -> `litellm.acompletion(stream=True)` and reconstructs streamed tool calls.
  - `UsageSummary` already supports fixed zero cost plus `actual_model` and `upstream_provider`.
- `src/tianshu/providers/manager.py`
  - `ProviderManager.get_client()` is the app-level selection boundary.
  - `_fallback_client()` uses `ConfigManager.state` and does not mean runtime fallback-on-error; live LiteLLM Router error fallback remains configured elsewhere.
  - `sync_all()` persists/deletes provider rows; it must not persist or activate demo, otherwise a later live startup could implicitly remain in demo.
- `src/tianshu/config.py:TianshuSettings` has `llm_model/key/base` but no startup profile. Default model is live `gpt-4o-mini`.
- `src/tianshu/config_manager.py:ConfigManager.__init__()` loads DB first and only seeds the supplied initial state when DB configs are empty. A demo environment value alone therefore cannot override an existing live DB safely.
- `src/tianshu/bootstrap/wiring_llm.py:wire_llm_config()` creates the initial state; `wire_provider_and_agent()` calls `ProviderManager.sync_all()`.
- Main governed calls use this boundary through `Agent.execute()` -> `ProviderManager.get_client()`, but direct `LLMClient` construction still exists in Planner, LLM reviewer, memory/compaction, and other helpers. Therefore the exact demo model must also dispatch inside `LLMClient`, not only in `ProviderManager`.
- `Agent._call_llm_with_recovery()` has an explicit configured live fallback. Demo must prevent a live primary/fallback config from entering this path; live exceptions must never select demo.
- `Agent._handle_llm_response()` accepts the existing tool-call form `{"id","name","args"}` and can execute deterministic `write_file` T1 calls through the normal governed staging context.

### Startup/profile and normal demo flow

- `src/tianshu/app.py:lifespan()` wires storage/resources/tools/config/provider/worker/executor/scheduler, starts scheduler, then yields.
- `Planner.plan()` can be skipped by an explicit `assigned_persona_id`; when exercised it requires valid JSON `PlanTask` fields. `DEFAULT_EXECUTOR_ID` is `bingbu`.

### Doctor

- `src/tianshu/cli/commands/doctor.py:DiagResult` only has display name/level/detail/hint.
- `_check_api_key()` leaks a key prefix.
- `_check_db()` calls `mkdir()`, writes `.doctor_probe`, and unlinks it; default Doctor therefore mutates HOME.
- `_check_workspace()` prints resolved absolute paths; `_check_db()` and exception text can print secret-bearing paths.
- `_check_port()` performs a loopback `/health` request. `_check_llm()` is correctly opt-in via `--llm`, but raw provider errors can contain URL query/header/token material.
- `doctor()` only renders a Rich table; it has no schema version, stable ids, JSON, required/optional field, or deterministic serialization.
- `tests/cli/test_doctor.py` only tests aggregate text/exit codes and relies on host extras/permissions; it does not test no writes, stable JSON, or redaction.
- Existing `tianshu.security.redact.redact_text()` is useful defense-in-depth but does not justify emitting raw diagnostic values. Doctor should emit allow-listed evidence fields and stable error codes, not sanitize arbitrary raw exceptions after the fact.

### Liveness/readiness and consumers

- `src/tianshu/app.py:create_app()` defines constant `/health` and `/health/live`; `/health/ready` is absent.
- `src/tianshu/gateway/auth.py:SecurityBoundaryMiddleware._public_route()` already includes GET/HEAD for `/health`, `/health/live`, `/health/ready`. A secure-remote public route bypasses auth context entirely; the minimal safe contract is therefore summary-only for every secure-remote readiness response. Detailed authenticated readiness would require a separate optional-auth middleware change and is not needed for this slice.
- `Scheduler` only exposes private `_running`; `start()` sets it before restoring jobs and creates review/orphan/system tasks; `stop()` clears it. There is no stable readiness property or failed-task check.
- `WorkerPool` has no lifecycle flag; it is usable immediately after construction and still has no explicit closed state after `shutdown()`.
- `WorkspaceService` has `_closing` and a concurrency-safe `shutdown()`, but no public readiness property. This file is currently owned by G1.4b3 and must only be touched after that work lands.
- DB/migration read checks can reuse `pending_migrations()` and SQLite `PRAGMA quick_check` in read-only/query-only mode. `Storage.init_db()` is mutating and must not be reused by Doctor.
- Host capability evidence already exists in `probe_host_capabilities()`. A detected Docker/Podman executable is only best-effort evidence, not a proven strong sandbox.
- `web/src/api/health.ts:getHealth()` calls `/health`; `useHealth()` polls it; `HealthDot` only recognizes `status === "ok"`.
- `scripts/local.sh:wait_healthy()` and `cmd_status()` use `/health`. `src/tianshu/cli/commands/health.py` also uses `/health`.
- `scripts/docker.sh` still uses `/health`, but container work belongs to G1.6 and should remain outside this slice.

## Minimal TDD slices

### B1 — explicit demo at the common dispatch boundary

Contract:

- Add `startup_profile: Literal["live", "demo"] = "live"` and exact constants `DEMO_MODEL = "mock/tianshu-demo"`, provider `demo`.
- `startup_profile=demo` creates a runtime-only config override: it masks existing DB live configs but is never inserted/activated in `llm_configs` or synchronized into persistent provider rows. Leaving demo therefore returns to live behavior, never an implicit demo fallback.
- In demo, `ConfigManager.state`, named config resolution, and `ProviderManager.get_client()` must resolve only the runtime demo state. Provider/persona overrides cannot escape to live network.
- `LLMClient` delegates only the exact model `mock/tianshu-demo` to a small deterministic backend before any LiteLLM/Router call. Other models remain unchanged.
- Deterministic response selection depends only on messages/tools, never mutable call counters: planner JSON, audit JSON, a stable `write_file` tool call when that tool is available and no tool result exists, then a final `[DEMO]` response after the tool result. Chat and stream return identical final semantics.
- Every response has zero token/cost counters, `actual_model="mock/tianshu-demo"`, `upstream_provider="demo"`; tool ids/arguments and JSON are canonical and stable.
- Streaming yields cancellable awaits and does not catch `CancelledError`.
- A live provider/Router exception propagates through existing live error handling and never invokes demo.

RED tests (write first):

1. `test_demo_requires_exact_opt_in_profile_and_model` — live profile cannot silently select demo; demo profile resolves exact constants and clears runtime credentials.
2. `test_demo_runtime_override_does_not_persist_or_replace_live_config` — existing live DB remains byte/logically unchanged before/after demo startup; next live startup sees the original active config.
3. `test_demo_chat_is_deterministic_zero_cost_and_never_calls_litellm_or_socket` — monkeypatch both LiteLLM and non-loopback socket use to fail; repeat call equality.
4. `test_demo_tool_response_is_stable_and_shaped_for_agent` — exact `write_file` call id/name/canonical args, then `[DEMO]` final response.
5. `test_demo_stream_matches_chat_and_cancellation_propagates` — delta order/final usage plus cancelled consumer raises `CancelledError`.
6. `test_demo_planner_and_audit_payloads_parse_with_production_models` — feed output through `Planner._extract_json`/`PlanTask` and `AuditResult` parsing.
7. `test_live_provider_error_never_falls_through_to_demo` — live LiteLLM/Router error remains an error; demo backend spy is untouched.
8. `test_governed_demo_edict_uses_normal_agent_tool_path` — real Storage/EventBus/Agent/WorkspaceService, explicit isolated governed contract, `bingbu`, T1 `write_file`, `[DEMO]`, zero cost, persisted lease/restore/change evidence, source unchanged.

### B2 — versioned read-only Doctor

Add a pure report module. Suggested exact model:

- `DoctorCheck(id, status, required, evidence: dict, remediation)`; statuses `pass|degraded|fail|skipped`.
- `DoctorReport(schema_version="1", status, checks)` with fixed check order, canonical `to_json()` (`sort_keys=True`, compact separators, UTF-8) and deterministic plain table renderer.
- Stable ids: `runtime.profile`, `auth.mode`, `provider.config`, `database.connectivity`, `database.migrations`, `resources.package`, `overlay.writable`, `workspace.git`, `server.port`, `server.live`, `server.ready`, `sandbox.capability`, `mcp.integration`, `optional.feishu`, `optional.telegram`, `build.identity`.
- Default runner performs no mkdir/write/migration/provider call. Missing fresh-HOME DB is `degraded` with `created=false`, not a fatal install failure. Existing DB is opened via SQLite URI `mode=ro`, `PRAGMA query_only=ON`; migration prefix and quick-check are read only.
- Evidence is allow-listed booleans/enums/counts/hashes only. Never emit key prefixes, raw values, headers, cookies, URL queries, absolute paths, usernames, or raw exception strings. Convert failures to stable codes/categories; `redact_text()` remains a final guard only.
- `--llm` remains an explicit network/cost opt-in; default Doctor is read-only and zero-network except optional loopback live/ready probes. `--format table|json` selects renderer; required failures produce exit 1 in both formats.

RED tests:

1. `test_doctor_json_is_canonical_versioned_and_order_stable` — two runs with controlled inputs are byte-identical JSON.
2. `test_doctor_table_and_json_share_the_same_checks_and_exit_status`.
3. `test_doctor_default_makes_no_files_and_never_constructs_llm_client` — snapshot fresh HOME tree and patch mutating/open-network operations.
4. `test_fresh_home_missing_database_is_diagnosed_without_creation`.
5. `test_existing_database_is_opened_read_only_and_pending_or_drifted_migrations_fail`.
6. Parameterized red-team test injects secrets into API key, base URL query, header/cookie-like errors, token prefixes, HOME/workspace/DB paths, exception messages; assert none of the raw strings or identifying substrings appears in JSON/table.
7. `test_every_check_has_stable_id_status_required_evidence_and_remediation`.
8. `test_optional_integrations_degrade_but_do_not_fail_unless_enabled_and_required`.

### B3 — live/ready and visible demo status

Contract:

- `/health/live`: only event-loop/process responsiveness; 200 with `{"schema_version":"1","status":"live"}`.
- `/health/ready`: 200 for `ready` or optional-only `degraded`; 503 for `not_ready`.
- Required independent checks: DB connectivity, migration prefix/integrity, scheduler, worker pool, packaged resources, provider/profile, WorkspaceService. Sandbox is fatal only when a currently enabled feature actually declares it mandatory (for example secure-remote code/universe execution); mere Docker/Podman detection is not proof. MCP and unconfigured optional integrations only degrade.
- Trusted-local detail may include fixed-id checks and `profile`. Secure-remote public response is exactly `schema_version,status`; no evidence/remediation/internal names. This matches the current public-route middleware without expanding auth scope.
- Keep legacy `/health` temporarily as the old liveness-compatible response to avoid unrelated breakage, but move all owned consumers to `/health/ready`.
- Add public `Scheduler.is_ready`, `WorkerPool.is_ready`, `WorkspaceService.is_ready`. Scheduler readiness requires running plus live mandatory background tasks; WorkerPool becomes false after shutdown; WorkspaceService is false once closing.
- Web `HealthDot` consumes readiness, distinguishes ready/degraded/not-ready, and visibly labels demo when trusted-local detail reports `profile=demo`.

RED tests:

1. `test_liveness_remains_200_when_every_dependency_is_unready`.
2. Parameterized `test_each_required_readiness_failure_returns_503_independently` for DB, migrations, scheduler, worker, resources, provider/profile, workspace, mandatory sandbox.
3. `test_optional_mcp_and_optional_dependency_failures_return_200_degraded`.
4. `test_secure_remote_anonymous_ready_body_has_exactly_schema_and_status` including 503 case and secret-injected internals.
5. Lifecycle tests for scheduler mandatory task death, WorkerPool post-shutdown, WorkspaceService closing.
6. `test_local_start_waits_for_ready_not_live` in `tests/scripts/test_local_sh.py`.
7. Web test: ready/demo/degraded/error rendering and polling `/health/ready`.

### C — one exact-wheel, fresh-HOME black box

Keep all process orchestration in `tests/packaging/test_fresh_wheel_demo.py`; do not add a production launcher or another shell script.

Test sequence:

1. Build once with `uv build --wheel --out-dir <temp>` and require exactly one wheel. Record SHA-256 and a sorted ZIP manifest (including METADATA/RECORD identity).
2. Create a repo-external venv and HOME/cwd/workspace/staging paths containing spaces and non-ASCII. Initialize/commit a clean Git source fixture.
3. Install dependencies and that exact wheel by absolute file URI with the `cli` extra. No editable install, repo path, second wheel build, or source-tree import is allowed.
4. After installation, install a test-only `sitecustomize` socket guard into the venv (not the wheel). Permit only loopback and AF_UNIX; reject DNS/non-loopback connects. Then run with `PYTHONPATH` removed, `PYTHONNOUSERSITE=1`, `PYTHONDONTWRITEBYTECODE=1`, fresh HOME, `startup_profile=demo`, and repo-external cwd. Assert a probe's `sys.path` contains neither repository nor source tree.
5. Run `tianshu doctor --format json` before API startup; assert schema/check ids/no secrets/no DB creation by Doctor.
6. Start the installed API with `venv/python -m uvicorn tianshu.app:create_app --factory` in a new process session. Poll `/health/live` then `/health/ready`.
7. GET `/`, `/brand.png`; assert static Web works and logo hash is the required value. GET `/api/departments` (exact six ids after Slice A migration) and `/api/skills` (builtin `shell`,`file-ops`).
8. Submit one explicit isolated/governed native contract with base revision, network deny, assigned persona `bingbu`, and a deterministic goal. Poll its memorial to terminal. Assert `[DEMO]`, all usage/cost zero, actual model/provider demo, no external-network guard violation.
9. Use root memorial id as workspace run id; GET current G1.4 final `/api/workspace-runs/{id}/status` and `/changes`. Assert lease, restore point, non-empty canonical change evidence, governed apply mode, and unchanged source bytes/HEAD/index/status because no apply decision was issued.
10. SIGTERM the process group, require clean exit within timeout, port closed, no surviving process group, no `ResourceWarning`/unclosed SQLite text. Run `PRAGMA quick_check` on the HOME DB.
11. Re-hash wheel and installed package RECORD files (ignore no files by setting no-bytecode); assert package digest unchanged. Emit a canonical evidence JSON containing wheel hash/manifest, OS/arch/Python, test profile, logo hash, and shutdown/DB results.

Mark the test `slow` and run it explicitly in release verification. A later CI job may run the same test on Ubuntu/Python 3.12; do not fork the test logic.
