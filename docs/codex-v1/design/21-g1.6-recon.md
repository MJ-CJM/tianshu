## 2. Slice A - append-only system audit and admin API (`N+1`)

### Current behavior and gaps

- `SecurityBoundaryMiddleware._required_scopes(path)` grants ordinary `/api/**`
  routes with `api`; only `/api/auth/tokens` is admin-only.
- Public session/refresh routes generate a middleware correlation id but do not
  put it in request state. `AuthService.create_session()` and
  `refresh_session()` generate separate ULIDs, so a denial cannot be joined to
  the inbound request.
- PAT issue/rotate/revoke and session family writes use `AuthMixin` transactions
  without durable audit.
- `EstopManager._persist()` writes state, updates memory, then its API emits an
  unrelated best-effort event.
- There is no retention/export/chain-integrity surface.

### Minimal persisted contract

Append migration `N+1` with one table and immutable triggers:

```text
system_audit_events(
  sequence INTEGER PRIMARY KEY,
  id TEXT NOT NULL UNIQUE,
  schema_version TEXT NOT NULL CHECK(schema_version = '1'),
  correlation_id TEXT NOT NULL,
  actor_digest TEXT NOT NULL CHECK(length(actor_digest) = 64),
  action TEXT NOT NULL,
  outcome TEXT NOT NULL,
  reason_code TEXT NOT NULL,
  subject_kind TEXT NOT NULL,
  subject_digest TEXT NOT NULL CHECK(length(subject_digest) = 64),
  metadata_json TEXT NOT NULL DEFAULT '{}',
  previous_hash TEXT NOT NULL CHECK(length(previous_hash) = 64),
  event_hash TEXT NOT NULL UNIQUE CHECK(length(event_hash) = 64),
  created_at TEXT NOT NULL
)
```

Add indexes for `(correlation_id,sequence)` and `(action,sequence)`. Add
`BEFORE UPDATE` and `BEFORE DELETE` triggers that always `RAISE(ABORT, ...)`.
The genesis previous hash is 64 zeroes. Hash canonical UTF-8 JSON containing
every persisted field except `event_hash`; metadata must already be canonical
and action-schema validated.

Do not accept an arbitrary metadata dictionary. Keep an action-to-allowed-keys
map beside `SystemAuditEventV1`; reject unknown keys. Persist digests, stable
reason codes, booleans/counts, scope names, key-name lists, and config/tool-set
hashes only. Never persist raw principal ids/display names, tokens, cookies,
headers, env values, URLs, URL paths/queries, source IPs, request/response
bodies, process output, or exception text.

Repository rules:

- `_append_system_audit_unlocked(conn,event)` is the single low-level append and
  assumes an already-owned transaction.
- standalone denial append begins `BEGIN IMMEDIATE`, reads the last sequence/hash,
  appends, verifies, commits;
- auth/estop/MCP state methods perform the governed DML first, then call that
  helper under the same Storage lock/SQLite transaction; append failure rolls
  back the state change;
- pagination is cursor-by-sequence, bounded, and verifies the predecessor anchor
  plus every returned event; export verifies the complete chain before emitting;
- retain indefinitely in G1. No delete/retention endpoint.

Admin surface:

- `GET /api/audit/system?after=<sequence>&limit=<bounded>`;
- `GET /api/audit/system/export` (canonical JSONL or one canonical JSON bundle
  with start/end sequence and terminal hash);
- both require `admin`; anonymous and `api`-only principals receive 401/403;
- chain corruption returns a stable failure, never partial "verified" output.

Required initial actions are `auth.token.issued`, `auth.token.rotated`,
`auth.token.revoked`, `auth.session.denied`, `auth.session.rotated`,
`auth.session.revoked`, `estop.engaged`, and `estop.resumed`. Slice B adds MCP
config/admit/deny/grant/spawn-terminal actions without changing the v1 schema.

## 3. Slice B - MCP ciphertext, remote admission, stdio grants (`N+2`)

### Current behavior and gaps

  Fernet codec, but `get_vault()` returns `None` when the key is missing and MCP
  persistence does not use it.
- `MCPServerConfig.enabled` defaults true; `_MCPServerCreate.enabled` defaults
  true; `ToolFilter.include=[]` means all discovered tools.
- `MCPManager._admitted()` admits all when its optional name allowlist is empty.
- remote transport passes URL/headers to the MCP SDK. The SDK default client
  follows redirects and inherits the environment; current code supplies no
  URL/IP/DNS policy and does not validate the actual connect target.
- `MCPManager` catches config-load failures and degrades to no overrides, which
  is not an acceptable plaintext/corrupt-ciphertext fallback.
- stdio does use `ExecutionGateway` and has process-tree timeout/cancel/shutdown
  receipts. Its grant is in-memory, based on the current configured argv, and
  receipts explicitly say `transitional_mcp_config_g1_6_pending`.
- current stdio grant does not bind executable realpath/content/stat, reason,
  approved tools/config hash, or a persistent grant row. The call to mint it
  also omits the available workspace/environment binding.

### `N+2` migration contract

Rebuild `mcp_server_overrides` in the migration transaction. Preserve every
non-secret column and NULL-vs-explicit-empty override semantics, but replace:

```text
env_json        -> env_ciphertext BLOB + env_keys_json TEXT
headers_json    -> headers_ciphertext BLOB + header_keys_json TEXT
```

Each ciphertext/key-list pair is both NULL (inherit/not supplied) or both
non-NULL. Encrypt compact, sorted-key canonical JSON of the entire mapping;
key-list JSON contains sorted names only. Before any CREATE/INSERT/DROP source
mutation, read all legacy rows, validate JSON/types, detect whether any mapping
is non-empty, obtain/validate the master key, encrypt all rows in memory, and
round-trip decrypt/compare. Missing/invalid key with a non-empty mapping raises a
stable migration error containing no value. There is no plaintext fallback.

Set SQLite secure deletion for the rebuild and add raw-file/WAL sentinel tests;
dropping a legacy table without proving bytes are gone does not meet the brief.
The existing pre-migration online backup is intentionally raw recovery evidence:
when the legacy columns exist, mark the backup name/metadata `legacy-sensitive`,
keep mode 0600, never expose contents, and exclude DB/WAL/SHM/backup patterns
from image/release contexts. The active DB and every post-migration backup must
not contain the sentinel. A failed migration preserves the original DB and raw
legacy-sensitive backup.

Create immutable grant facts plus append-only grant states:

- `mcp_stdio_grants`: id/schema, server identity digest, complete canonical
  principal JSON + digest, non-empty reason, issued/expiry, executable realpath
  + SHA-256 + canonical stat fingerprint, exact argv JSON/hash, config hash,
  workspace lease/root digest, env-key/reference names, network/sandbox
  contracts, non-empty approved tool set/tool-set hash, created_at.
- `mcp_stdio_grant_states`: `(grant_id,version)` primary key; first state
  `issued`, one terminal `consumed|revoked|expired`; contiguous-state trigger.

Do not FK grants to `mcp_server_overrides`: YAML-seeded servers need grants too.
Consume a grant once before spawn; a failed spawn still consumes it. Reconnect
requires a new grant. Config, executable/stat/content, argv, workspace/lease,
env names/references, network/sandbox, principal, or discovered/approved tool-set
drift denies before spawn and appends safe audit.

### Remote policy

Add one policy boundary before the SDK:

- HTTPS only; no userinfo, query, fragment, encoded host tricks, non-canonical
  numeric host, or unsafe port;
- resolve A/AAAA; DNS failure or any mixed unsafe answer denies;
- reject unspecified, loopback, private, link-local, CGNAT, metadata,
  benchmarking, documentation, multicast, reserved and future-use ranges;
- recursively reject unsafe IPv4 embedded in IPv4-mapped, 6to4 or Teredo IPv6;
- custom MCP `httpx_client_factory` uses `trust_env=False`,
  `follow_redirects=False`, no proxy, and a transport/network backend pinned to
  the validated address while retaining TLS SNI/hostname verification;
- validate the actual connect address and deny DNS answer change/reconnect drift;
- DNS is described only as preflight/pinning input, never "rebinding protection"
  without a real egress enforcement boundary;
- `secure-remote` denies all remote MCP with reason
  `trusted_egress_unavailable` in this release. Do not add a boolean escape
  hatch; no verified trusted-egress implementation exists in the repository.

Audit stores server/host/path/config digests and policy codes, never raw URL,
query, headers, DNS error text, or response bodies.

### Stdio policy

- New stdio servers default disabled in the API and DB-only merge path.
- An enabled stdio server with an empty approved include set is denied and
  registers zero tools. Exclude-only/all-discovered is not approval.
- Grant issuance is admin-only and binds the authenticated complete principal.
- Resolve the command through a controlled PATH, require a regular executable,
  store realpath/content/stat fingerprint and revalidate immediately before
  `ExecutionGateway.start()`.
- Extend `CommandGrant`/`ExecutionRequest`/`ExecutionReceipt` with the persistent
  grant id/hash and exact bindings; replace the transitional marker only after
  the persistent grant is actually verified.
- Keep spawn/termination in `ExecutionGateway`; the manager may not add a second
  subprocess path. Receipt callback appends terminal system audit with status,
  timing/counts and hashes only, never stdout/stderr.
- Intersect discovered tools with the grant's exact approved set. Unknown/newly
  discovered tools remain unregistered until a new config/grant.
- `/api/mcp` PATCH/POST/DELETE/reload and grant/admission routes require admin.
  Ordinary safe GET views may remain `api`; external `/mcp` keeps its existing
  `mcp:read`/`mcp:submit` boundary.
