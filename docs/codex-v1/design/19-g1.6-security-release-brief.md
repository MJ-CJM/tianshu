# G1.6 — MCP admission security, system audit, container, CI, and threat model

## Objective

Close G1's remaining public-release security gates: encrypted MCP secrets,
fail-closed remote/stdio admission, persistent system audit, a non-root release
container definition, reproducible CI/release evidence, and a truthful threat
model.

## Scope and invariants

- Use new migrations after G1.4/G1.5's final version; never rewrite v2/v3 or any
  shipped checksum.
- Reuse the low-level secret codec without making migrations depend on a
  high-level settings/service object.
- Persistent audit records contain allowlisted metadata only; never secret
  values, raw headers, credential-bearing URLs, queries, or output bodies.
- `trusted-local` remains convenient only on verified loopback. `secure-remote`
  is fail-closed and cannot advertise unverified trusted egress/sandbox claims.
- Existing MCP stdio ExecutionGateway receipts are transitional evidence, not a
  substitute for persistent admission grants and system audit.

## TDD sequence

### A. Frozen migration and encrypted persistence

1. Freeze/checksum all prior migrations, add RED upgrade tests from representative
   legacy MCP env/header mappings and backups.
2. Migrate secret values to ciphertext with non-secret key metadata. Assert the
   active DB, backups, audit, logs, doctor, and API never contain sentinels.
3. Missing/invalid master key with a non-empty legacy secret fails closed before
   source mutation and preserves the original DB plus verified backup.
4. Key rotation and corrupted ciphertext fail explicitly; no plaintext fallback.

### B. Remote MCP policy

1. RED negative matrix: non-HTTPS, file/userinfo, private/loopback/link-local,
   metadata/reserved/documentation/multicast, IPv4-in-IPv6/encoded/mixed answers,
   DNS failure/change, redirect, credential/query leakage.
2. Disable redirects and proxy inheritance; validate the actual connect target.
3. In secure-remote, remote MCP is denied unless a separately configured,
   verified trusted egress boundary is present. DNS preflight alone is never
   described as rebinding protection.
4. Persist denial/admission audit with correlation, actor, policy reason, and
   safe endpoint identity only.

### C. Stdio admission

1. New stdio server defaults disabled and exposes no discovered tools.
2. Require short-lived grant bound to complete principal, reason, expiry,
   executable realpath and digest/fingerprint, exact argv, workspace/lease,
   permitted env-key names/references, network/sandbox policy, and config hash.
3. Config/executable/workspace/env/tool-set changes revoke the grant. Unknown or
   newly discovered tools are not registered beyond the approved set.
4. Spawn remains through ExecutionGateway; cancellation/timeout/shutdown reaps
   the process tree and emits terminal persistent audit.

### D. System audit and admin surface

1. Add append-only `system_audit_events` with stable schema/version/hash chain or
   equivalent tamper-evident linkage, correlation, actor digest, action, outcome,
   safe subject metadata, timestamps, and pagination.
2. Writes are transactional with the governed state change where feasible;
   write failure is fail-closed for security decisions.
3. Read/export requires explicit admin/audit scope in secure-remote; no anonymous
   detail leaks. Add retention/export integrity tests.

### E. Release container

1. Multi-stage build: frontend builder, frozen wheel/dependency builder, minimal
   Python runtime. Runtime contains no Node/compiler/build cache or source tree.
2. Fixed non-root UID/GID, explicit writable volumes, least privilege, readiness
   healthcheck, and the exact tested wheel/profile/assets.
3. Smoke (when Docker daemon exists) with read-only rootfs, fresh volumes,
   network-disabled demo, desktop Web/logo/resources, doctor/readiness, governed
   mock Edict, restart, and clean shutdown.
4. If the daemon is unavailable, validate syntax/static policy and record runtime
   smoke as unverified, not passed.

### F. CI, release, SBOM, and threat model

1. Add frozen sync/export, backend and desktop Web gates, wheel/fresh-install,
   container smoke, dependency/code/secret scanning, Python/Web SBOM, artifact
   hashes/signatures/provenance hooks, and Developer Preview dry-run release.
2. A scanner/tool unavailable state fails or is clearly unavailable; it never
   becomes a clean result.
3. Workflows use least permissions, pinned actions, no pull-request secret
   exposure, concurrency controls, and artifact retention.
4. Document assets/trust boundaries/attack paths/mitigations/residual risks for
   auth/TLS proxy, MCP, external executors, sandbox, workspace/apply, Web/WS,
   self-evolution, backup/master secrets, audit, supply chain, and single-node
   operation.

## Required verification

- MCP migration/secret/remote/stdio/admission/audit negative and lifecycle tests.
- Auth, route matrix, ExecutionGateway, doctor/readiness, wheel/demo regressions.
- Dockerfile/workflow/security-doc truth tests; runtime container smoke only when
  a real daemon is present.
- Ruff, format check, official mypy, import-linter, full non-slow pytest, Web
  lint/typecheck/tests/build, clean status.
- One implementation commit, independent security/spec/quality review, and fix
  all Critical/Important findings before G1 final gate.

## Honest limits

- No trusted-egress claim without an actual enforcement boundary.
- No container runtime/multi-arch claim without daemon-backed evidence.
- GitHub OIDC, signing, public registry publication, and external Linux/Python
  matrix evidence remain pending until executed in those environments.
