# 天枢 Agent OS Web 审批稿设计

> 状态：目标设计，当前原型仍有术语、门禁和指标偏差；正式执行以 `2026-07-10-open-source-agent-os-optimization-design.md` 与配套 Master Roadmap 为准。

## 目标

制作一个与生产前端完全解耦的可点击 Web 原型，用于逐页审批天枢的新产品管控面。原型只使用模拟数据，不访问后端，不修改 `web/` 生产代码，也不进入生产构建。

产品定位固定为：

> 天枢是一个可治理、可验证、持续成长的自进化 Agent OS。

本轮要验证的不是完整业务能力，而是三个产品问题：

1. 用户能否从首页立即看清系统正在办什么、哪里需要人决策、风险和预算是否受控；
2. 用户能否沿一条敕令看到契约、执行、证据、裁决、成本和结案的完整治理链路；
3. 用户能否理解成长不是任意自改，而是经过回归评测、小流量验证、人工晋升和可回滚的受控演化。

## 边界

- 新建独立目录 `prototypes/tianshu-agent-os/`，自带依赖与启动脚本。
- 不复用生产 API，不创建登录、持久化、真实裁决或真实执行能力。
- 不修改 `web/src/`、`src/tianshu/` 或现有路由。
- 只实现三条审批路线：中枢总览、敕令详情、演化中心。
- 本轮只审批桌面网页端，不开发或验收手机端。
- 页面视觉审批前不迁移到生产代码，也不提交原型改动。

## 治理术语

- 面向用户的人工治理动作统一称为 `裁决`，状态使用 `待裁决 / 等待裁决`，入口使用 `查看并裁决`。
- 敕令详情中的专用栏目称为 `人工裁决`；批准、驳回、修改、重试和撤销均属于裁决结果。
- 目标原型不得使用 `批红` 或 `司礼监代批`；当前源码仍待 Phase 0 迁移，避免把未完成修正写成既成事实。
- 生产系统现有 `Decree` 数据模型、API 路径和代码标识作为兼容实现暂不改动，也不在当前网页端暴露。

## 视觉来源与设计原则

视觉来源：

- `/tmp/tianshu-figma-home.png`：中枢总览的主要构图、密度与层级；
- `/tmp/tianshu-figma-task.png`：敕令详情的契约、脉络、决策和证据布局；
- `/tmp/tianshu-ui-audit/04-universe-empty.png`：现有位面功能的语义来源；
- `docs/strategy/2026-07-09-ui-refresh-zhupi.md` 与 `web/src/theme/palette.ts`：正式色板和“朱批”设计宪法。

视觉原则为“墨为骨、朱为睛、纸为气”：

- 宣纸暖白、烟墨、黛青和低饱和器物色构成主体；
- 朱砂只用于待裁决、风险、当前选中与键盘焦点；
- 采用宋体标题、黑体正文、等宽数字，保持新中式但不复古堆砌；
- 不使用霓虹、强渐变、大面积金色、宫殿纹样或装饰性龙纹；
- 卡片以边线和留白区分，不使用浮夸玻璃效果与重阴影。

## 信息架构

### 全局框架

- 顶栏沿用现有产品框架：使用现有天枢 Logo，不改变品牌图形；保留品牌标语、`彩蛋 / 通用 / English`、`实时 / 通政`。
- 左侧固定首项：`中枢总览`，用于跨部门治理总览。
- 原部门导航完整保留并默认展开：
  - 敕令：御书房、文书房；
  - 政要：内阁、廷议、都察院、权印司；
  - 百官：百官阁、文渊阁、位面、考成；
  - 外朝：藏兵阁、鸿胪寺、通政司、户部账房。
- 只有当前项、待裁决数量和风险数量使用朱砂；其他部门使用克制的墨灰图标。
- 侧栏底部保留主题切换与收起侧栏；收起后只显示图标，并可再次展开。
- 删除无明确操作含义的“系统可信 / 执行器可用”侧栏摘要；任何可信度指标都必须有分子、分母、时间窗和下钻证据。

### 中枢总览

- 今日态势：办理中、待裁决、预算、证据完整率、异常/恢复。
- 进行中的敕令：目标、执行器、部门、进度、里程碑和当前阻塞。
- 当前待裁决：风险原因、拟执行动作、权限边界与决策入口。
- 成长脉动：新增可信记忆、技能候选和最近复盘结论。
- 成长与演化：候选版本、评测得分、回归集、Canary 进度及晋升门槛。

### 敕令详情

- 顶部执行契约：执行器、风险、预算、期限与工作区。
- 页签：总览、计划、脉络、证据、变更、裁决、成本、结案。
- 执行脉络：规划确认、策略检查、待高风险裁决、独立验收。
- 当前需要决策：驳回、修改后批准、批准；高风险批准必须填写理由并展示影响范围和恢复点，操作后展示明确反馈。
- 证据包：变更证据、验证证据、治理证据，强调“执行者不能自证完成”。

### 演化中心

- 候选变更摘要：变更对象、来源、假设、影响范围和可回滚点。
- 晋升流水线：提案、离线回归、安全评测、Canary、人工晋升。
- 对比面板：当前冠军与候选位面的质量、安全、成本、稳定性差异。
- 评测集明细：历史回归、高风险用例、Canary 样本和证据完整度。
- 决策区：驳回候选、继续观察、批准晋升；强门未满足时晋升禁用，紧急覆盖走单独高风险裁决，任何决定均保留依据。

## 交互

- 左侧导航在三页之间切换，非本轮页面显示“保留的部门入口”提示，不创建额外页面。
- `彩蛋 / 通用 / English` 可切换选中态；正式翻译内容不在本轮原型范围内。
- 主题切换和侧栏收起/展开均可操作，并沿用现有产品的交互位置。
- 敕令卡片可进入详情；返回动作回到中枢总览。
- 页签、裁决按钮、主题切换、侧栏收起和演化阶段筛选可操作。
- 裁决和晋升动作只更新当前浏览器内的模拟状态，并提供撤销或回到初始状态的方式。
- 所有交互具备 hover、focus、selected 与 disabled 状态；尊重 `prefers-reduced-motion`。

## 桌面适配与可访问性

- 桌面基准：1440 × 1024，并检查 1280px 宽度；内容区在更宽屏幕保持合理最大宽度。
- 本轮不以手机视口作为交付或验收条件。
- 正文最小 13px，关键文本和控件满足 WCAG AA 对比度；交互元素支持键盘操作并具备可读标签。

## 验收

- 三个目标页面均可从导航直达且主路线可操作。
- 所有页面使用真实业务措辞和模拟数据，无占位符、乱码或后端报错。
- 1440 × 1024 与 1280px 桌面宽度均无遮挡、横向溢出或不可达主操作。
- 自动测试覆盖导航、现有 Logo 与页头状态、主题切换、侧栏收起、裁决反馈和晋升反馈。
- 本地构建成功，浏览器控制台无错误。
- 设计 QA 分开记录 `Shell Fidelity` 与 `Product Integrity`；旧术语、无口径指标和门禁绕过全部清零后，才允许 overall `passed`。
