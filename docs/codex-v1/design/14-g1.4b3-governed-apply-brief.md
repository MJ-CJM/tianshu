# G1.4b3 — Governed apply, REST/CLI, capability truth

Start from reviewed G1.4a/b1/b2. Extend the single `WorkspaceService`; do not
create a parallel apply authority.

## TDD service contract

- Read status/preview only from persisted active lease, restore point, latest
  server-generated canonical change set, memorial/effective contract and source
  identity. Recompute before any decision and again before apply.
- Issue a high-entropy opaque token once; store only its hash. Bind immutable
  decision to full principal digest, `workspace` scope, explicit reason,
  source/repository identity and path, base/head/ref, restore point, lease,
  change-set id/hash, expiry, and CAS pending state.
- Apply under a source-level async/process lock:
  1. authenticate and validate token/principal/expiry/pending state;
  2. validate source path/repository/per-worktree authority, clean status,
     unchanged HEAD/ref/index/restore point;
  3. recompute canonical changes and compare the approved hash;
  4. atomically claim the decision so replay/concurrent apply loses;
  5. materialize only the approved canonical set, validating every path,
     symlink parent, mode, blob OID/size and binary content;
  6. on synchronous failure restore the exact source snapshot and verify bytes,
     modes, symlinks, untracked, index, HEAD/refs/status;
  7. persist immutable success/failed/denied receipt and terminal decision/lease
     state; close staging when safe.
- Source drift, stale hash, wrong actor, expired/revoked/consumed token, replay,
  cross-run/cross-repo binding and cleanup failure all fail closed with safe
  codes. No token, secret, raw header or unsafe diff enters logs/events/WS.
- Explicitly retain the host-crash gap between DB claim and filesystem effect;
  G1 proves synchronous rollback only, not exactly-once.

## Surface

- REST (the finalized B1 route contract uses an explicit status suffix):
  - `GET /api/workspace-runs/{run_id}/status`
  - `GET /api/workspace-runs/{run_id}/changes`
  - `POST /api/workspace-runs/{run_id}/apply-decisions`
  - `POST /api/workspace-runs/{run_id}/apply`
- Add `workspace:apply`; decision/apply POST requires it in secure-remote.
  Status/preview requires normal authenticated API access and never trusts actor
  data from the body.
- CLI `workspace status|preview|approve|apply`; token only via hidden prompt or
  stdin, never argv echo, URL or logs. Stable JSON/table output and exit codes.

## Capability truth and lifecycle

- Only after E2E applies/rollbacks pass, update capability evidence for
  `pre_run_restore_point` and `governed_apply_merge` on the exact tested
  adapters. Keep `workspace_control=best_effort`, side-effect receipts not
  upgraded, durable resume unsupported, and maturity contained.
- Expired/rejected/revoked decisions allow idempotent staging cleanup. Readiness
  exposes pending cleanup/identity drift safely.

## Verification

- Failure injection at every validation/materialization/restore/receipt step;
  stale/replayed/wrong-principal/expired/concurrent tokens; symlink redirect;
  add/modify/delete/rename/copy/mode/symlink/binary/non-UTF8 where supported;
  source and object-DB invariants; API auth matrix; CLI no-token-leak tests.
- Run Workspace/Git/storage/auth/API/CLI/Executor/DAG/Keqing/ExecutionGateway /
  migration/backup regressions, full quality gates and full pytest. Separate
  commit and independent security/spec review.
