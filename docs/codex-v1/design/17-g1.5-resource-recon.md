## Executive findings

1. **The current wheel is not self-contained.** It has 408 archive entries, but
   its only non-Python package payload is `tianshu/py.typed`; the license is present
   only under `.dist-info/licenses/`. Personas, 395 persona templates, builtin
   skills, Web assets, and the three executor Markdown templates are absent.
2. **Nine runtime consumers infer paths from `__file__`/`tianshu.__file__`.** Six
   are resource consumers that break after wheel installation; two are workspace/eval
   roots that must become explicit rather than be redirected to package resources;
   one executor-template consumer happens to resolve inside the package but still
   bypasses the required `importlib.resources` catalog.
3. **Three paths can mutate installed defaults today:**
   `PersonaLoader.delete()` removes `self._dir/persona_id`, `COURT.md` PUT writes
   beneath `app.state.personas_dir`, and `SkillsLoader.save_skill()` /
   `write_skill_file()` / `remove_skill_file()` may select the builtin directory.
4. **The current migration tail is exactly v4** (`0004_workspace_foundation`).
   Slice A must append v5 after G1.4 freezes v4; it must never edit v4's name,
   checksum, or statements.
5. **The desired six persona rows do not exist on a fresh DB today.** Existing
   `tests/gateway/test_personas_api.py::test_list_personas_empty_by_default`
   explicitly asserts the current empty behavior and must become RED/then be updated.

## 4. Overlay precedence and every relevant write/delete point

### Contract

- One explicit `data_root` (default may be `~/.tianshu`, but the resolved root is
  injected) owns writable personas, prompts/COURT, memory, skills, plugins, and
  file-backed config.
- Read precedence is `explicit workspace override > data overlay > packaged default`
  where a workspace override is already an intentional execution input; otherwise
  it is simply `data overlay > packaged default`.
- A write/delete API asks the overlay for a writable target. No caller derives a
  sibling from a packaged read path.
- Persona templates, Web assets, executor templates, license, and version metadata
  are immutable and have no runtime write API.

### Proven package-mutation bugs (must be RED first)

| File / symbol | Current mutation | Fix boundary |
|---|---|---|
| `persona/loader.py::PersonaLoader.delete` | `shutil.rmtree(self._dir / persona_id)` | delete only `self._runtime_dir/persona_id`; DB migration ledger prevents reseeding; never touch packaged `self._dir` |
| `gateway/system_api.py::_prompt_file_path,update_prompt_file` | `COURT.md` resolves to `personas_dir/court/COURT.md` and `write_text()` mutates the default | resolve reads overlay-first; all PUTs write `data_root/personas/court/COURT.md` |
| `skills/loader.py::SkillsLoader.save_skill` | scans workspace/user/builtin and writes the first existing `SKILL.md`, including builtin | copy-on-write/materialize into workspace or user overlay before edit |
| `skills/loader.py::_resolve_skill_resource,write_skill_file,remove_skill_file` | may return a builtin resource path, then write/unlink it | materialize the whole skill into the writable overlay before resource mutation |

`SkillsLoader.delete_skill/archive_skill/restore_skill` already iterate only
`_writable_dirs()` and therefore do not delete builtins. Preserve that property.

### COURT reset semantics

The frozen behavior for G1.5 is to remove the overlay override and fall back to
the current packaged `COURT.md`. Do not copy packaged bytes into the overlay:
that would turn a reset into a new mutable override and make later package
upgrades ambiguous. Test missing/already-absent overrides, fallback content,
overlay-precedence restoration after a later edit, and an unchanged package digest.

## 5. Default-persona migration

- Current tail: `src/tianshu/storage/migrations.py::MIGRATIONS[-1]` is
  `version=4`, `name="0004_workspace_foundation"`.
- Append `version=5`, suggested immutable name `0005_seed_default_personas`.
- The callback runs inside `migration_ledger.apply_migrations()`'s
  `BEGIN IMMEDIATE` transaction and must not call `commit`, `rollback`,
  `executescript`, or filesystem/resource readers.
- Algorithm:
  1. `SELECT COUNT(*) FROM personas`;
  2. if non-zero, return without inserting anything;
  3. otherwise `executemany` the six immutable seed rows;
  4. let the migration framework run FK/quick checks and write the ledger atomically.
- Do not use startup seeding. A deleted default stays deleted because v5 is already
  recorded and never reruns.
- `Storage._seed_departments()` currently runs after migrations and always ensures
  the six department records when the departments table is empty. The personas table
  has no department FK, so v5 can insert persona rows before that existing call; tests
  must cover the complete `Storage.init_db()` result.
- Existing behavior conflict:
  `tests/gateway/test_personas_api.py::test_list_personas_empty_by_default` must be
  replaced by an exact-six assertion. `test_list_departments` remains valid.

## 8. Dependencies and conflicts

- **Hard ordering:** start after G1.4. `migrations.py` is currently modified by
  active G1.4 work while v4 remains the tail. Re-read `MIGRATIONS[-1].version`
  immediately before implementation, append `+1`, and never edit an applied v4
  definition/checksum.
- Existing dirty overlaps at reconnaissance time include `app.py`,
  `storage/migrations.py`, workspace executor/gateway/model files, and related tests.
  Slice A directly overlaps `app.py` and `migrations.py`; coordinate/merge rather
  than overwriting concurrent edits.
- Moving the persona/template trees requires synchronized updates to the vendoring
  script and tests. A copied duplicate tree is smaller initially but creates an
  unacceptable source-of-truth drift risk.
- Changing `static_dir` default from `/app/static` can affect container packaging;
  retain explicit override precedence. Container validation belongs to G1.6.
- Six default personas intentionally change API/UI assumptions that a fresh DB is
  empty. Search for empty-state tests and do not paper over failures with conditional
  startup seeding.
- `TemplateLibrary` and `frontmatter.load()` are path-oriented. A catalog based on
  `Traversable` needs either reader adaptation or a correctly scoped `as_file()`
  lifetime; this is the main implementation design dependency.
- The Web build's external Google Fonts URL is a Slice C offline blocker even after
  all static files are packaged.
