# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

## Approved Tianshu direction

- Positioning: 天枢是一个可治理、可验证、持续成长的自进化 Agent OS。
- Style: restrained New Chinese control plane; 墨为骨、朱为睛、纸为气; no neon, ornamental palace motifs, heavy gradients, or theatrical gold.
- Navigation: keep the original four visible department groups and all fourteen department entries. Add 中枢总览 above them instead of replacing them with generic product categories.
- Brand shell: use the existing `web/public/brand.png` logo unchanged. Keep the original header tagline, `彩蛋 / 通用 / English`, `实时 / 通政`, plus the sidebar footer theme and collapse controls.
- Scope: approval-only prototype for 中枢总览、敕令详情、演化中心. Mock data only; do not connect production APIs or edit production frontend code.
- Device scope: desktop Web only for the current approval round; do not spend time developing or presenting a mobile version.
- Review boundary: keep the prototype local and uncommitted until the user approves the pages.
