## Delivered scope

- Extended the existing `ExecutionGateway` with explicit `null` / `pipe` stdin modes,
  bounded per-write input, `drain()`, close, byte-preserving stdout iteration, bounded
  receipt capture, backpressured streaming, and process-tree cleanup after cached completion.
- Added the `mcp_stdio` execution purpose and grant scope. The single bootstrapped gateway
  owns the HMAC signature and the current admitted `server name -> exact argv` mapping. Grants
  bind server identity, argv digest, effective-contract hash, correlation, scope, issue time,
  expiry, and signature; unknown, changed, forged, cross-server, cross-contract, and
  cross-correlation grants fail before spawn.
- Injected the same bootstrapped gateway into `MCPManager`, `MCPServerSession`, and the stdio
  transport. `tools/mcp/transport.py` no longer imports or calls SDK `stdio_client`,
  `StdioServerParameters`, or a process-launch API.
- Replaced SDK-owned stdio spawning with zero-capacity MCP `SessionMessage` streams backed by
  gateway pipes. JSON-RPC remains newline-framed and incremental; the whole session is not
  buffered. A 1 MiB per-message write bound and an eight-chunk gateway queue apply backpressure,
  while receipt stdout/stderr capture remains bounded at 1 MiB.
- Each stdio connection gets a system-service actor, unique correlation ID, current generated
  effective system contract, validated workspace root/cwd, explicit trusted-local or
  secure-remote sandbox/network posture, timeout, clean environment policy, and exact signed
  command grant.
- Stdio environment values must be exact `${ENV_REF}` references. The request and receipt record
  only child env key names and source refs; literal env values fail before spawn. Resolved values
  are redacted from streamed protocol output, final output, exceptions, logs, request
  serialization, and receipts. The streaming redactor now retains only a possible secret-prefix
  suffix, so it neither stalls JSON-RPC frames nor repeats short secrets inside its marker.
- Startup failure, malformed protocol, manager shutdown, task cancellation, gateway timeout,
  and reconnect all close streams and terminate/reap the process group. Timeout/process closure
  wakes the session lifecycle and reconnects. The latest terminal receipt is retained on the
  server runtime and exposed through `MCPManager.terminal_receipts` after shutdown/failure.
- Backend spawn failure now raises `ExecutionStartError` with a structured, zero-output terminal
  receipt. The pre-handle MCP transport callback retains it on session/manager state without
  serializing resolved secret values.
- `MCPManager` registers starting sessions and their tasks before yielding to initialize.
  Concurrent/repeated shutdown cancels and awaits those resources before closing connected
  sessions, including a sleeping initialize process with a descendant.
- After process-tree termination, stdout/stderr drains receive a bounded EOF window and are then
  cancelled if still blocked. A stopped pipe consumer cannot wedge terminate, timeout, or waiter
  cancellation; partial receipts mark the affected stream as both truncated and incomplete.
- MCP receipts explicitly label command admission as
  `transitional_mcp_config_g1_6_pending`; this is not represented as final G1.6 admission.
- Preserved MCP naming, filtering, tiers, handler behavior, and streamable-HTTP SDK transport.
  HTTP does not configure or start a local process.

## Truthful limits / concerns

- Trusted-local MCP stdio honestly uses host execution with unrestricted network and records
  `sandbox_enforced=false` / `network_enforced=false`. It does not claim child network isolation.
  Secure-remote requests require a sandbox and restrictive networking, so the current host
  backend fails closed before spawn.
- Admission is the explicitly labelled G1.3 transitional server-name/config allowlist. Versioned
  grants, executable realpath admission, config-revision revocation, encrypted MCP persistence,
  UI grants, remote SSRF policy, and durable audit remain G1.6.
- Stdio secret injection supports exact environment references only; literal/compound values are
  rejected. The backing resolver is still the process environment, not a keychain/secret service.
- Terminal receipts are in-memory runtime diagnostics, not a durable audit journal.
- POSIX/macOS process-group descendant cleanup is covered by real PID tests. Windows descendant
  cleanup is not proven; the gateway fallback can terminate only the direct process.
- Gateway protocol capture and each stdin message are bounded at 1 MiB. Protocol bytes continue
  streaming after capture truncation, but an individual message larger than the bound is rejected.
- Universe, Git, LSP, grep, eval, final repository-wide AST gates, DB/UI MCP defaults, and all
  other G1.6 work were intentionally untouched.
