# G1.3b3 implementation report

## Outcome

- Added a repository-wide AST process-launch gate. It resolves import aliases and
  simple assignments, rejects star/dynamic-import concealment, scans `src/tianshu`,
  `scripts`, and repository-root Python files (including untracked/new files), and
  fails both unknown launches and stale exact exemptions.
- Added one strict, synchronous, named `GitBackend`. Runtime callers have no public
  raw argv/command escape hatch; the only low-level launch is private
  `GitBackend._invoke`.
- Migrated `CodeVariantStore`, `CodeMutator`, `UniverseEvolver`,
  `PlatformEvalRunner`, and `ShadowSnapshot` to named Git operations while keeping
  their synchronous public APIs.
- Migrated ripgrep through a dedicated workspace-bound `grep` system-adapter grant.
  Its canonical argv includes `--` before the user pattern, so leading-dash patterns
  remain data.
- Added an async basedpyright core through a dedicated workspace-bound `lsp` grant.
  `edit_file` awaits it; unavailable, denied, timed-out, and failed diagnostics are
  structured advisory outcomes with correlation IDs. The sync compatibility wrapper
  rejects use inside an active event loop.
- Added controlled adapter executable resolution. Mutable `PATH`, workspace
  lookalikes, and a trusted executable that changes between grant issue and spawn-time
  validation are rejected. The active project runtime environment remains trusted, so
  the documented `uv run --extra lsp` installation resolves `.venv/bin/basedpyright`.
- Replaced the final process-launching persona sync script with pinned GitHub HTTPS
  archives, per-hop redirect allowlisting, proxy disablement, bounded downloads, and
  path-safe selective tar materialization.
- No `WorkspaceService` or apply workflow was added in this increment.

## GitBackend boundary

- Resolves Git once from `os.defpath`, executes an absolute path, and supplies a
  clean non-interactive environment with global/system configuration disabled.
- Disables hooks, fsmonitor, untracked cache, external diff/textconv, credential
  helpers, signing and signature verification, automatic GC/maintenance, recursive
  submodules, replace objects, and lazy fetch. Every invocation pins the caller's
  worktree, preventing repository-local `core.worktree` redirection.
- Validates refs, branch names, SHAs, messages, and pathspecs before launch. Pathspecs
  reject traversal, absolute/backslash/NUL/CR/LF paths, overlong paths, and every
  case variant of a `.git` component.
- Bounds runtime, stdin, stdout, stderr, blob size, aggregate materialization bytes,
  and staged path count. stdout/stderr are drained concurrently through pipes while
  retaining only the configured prefix; large child output is never accumulated in
  a temporary output file.
- Stages regular files with one `hash-object -w --no-filters --stdin-paths` call and
  one `update-index -z --index-info` call. A 1,000-file contract now uses five named
  invocations instead of approximately 2,000 child processes. Symlink targets are
  read by Python and hashed as link text.
- Performs the complete aggregate byte/path preflight before any blob write. Diff
  staging uses a private index and object database with the source object database
  read only through alternates, so uncommitted diff calculation does not pollute the
  source repository.
- Uses plumbing (`write-tree`, `commit-tree`, compare-and-swap `update-ref`) from an
  empty control worktree. The expected-old value is always present, including the
  object-format-specific zero OID for an unborn SHA-1 or SHA-256 repository.
- Materialization uses one bounded `cat-file --batch-check` plus memory-bounded
  `cat-file --batch` chunks, spools validated blobs before filesystem writes, and
  enforces per-blob, aggregate, and path-count limits. A 250-file worktree contract
  uses five named invocations instead of 503. Worktree create uses `--no-checkout`,
  avoiding repository-controlled clean/smudge processes.
- A malicious-repository sentinel covers hooks, fsmonitor, clean/smudge/process
  filters, textconv, external diff, and signing across stage, commit, diff, worktree
  create, and restore; no helper is invoked.

## Honest limits

- Fixed Git lifecycle operations are bounded and named but do not emit
  `ExecutionGateway` receipts; the native capability manifest states this explicitly.
- Filesystem checks and writes are fail-closed against static symlink parents, but are
  not an atomic `openat`/directory-FD transaction. A hostile same-UID writer can still
  race path replacement between validation and I/O. Workspace leases/ownership belong
  to G1.4.
- grep/LSP grants resolve an absolute executable from controlled install roots and
  recheck it immediately before spawn, but do not pin an executable file descriptor or
  digest; same-path binary replacement in the final check-to-exec window remains a
  same-UID TOCTOU limit.
- The default network-deny contract remains fail-closed on the non-enforcing host
  backend. grep records the denied receipt and uses its process-free Python fallback;
  LSP returns a structured denied advisory. External adapters run only when the
  effective contract explicitly resolves to unrestricted network or a future backend
  can attest enforcement.
- Existing gitlink entries are preserved during bulk staging; changed submodule HEADs
  are not advanced by this fixed-operation backend.
- Windows process behaviour and GitBackend path semantics were not exercised on this
  macOS host and are not claimed.
