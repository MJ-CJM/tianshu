# G1.3b2 implementation report

## Outcome

- Universe Gate and Sandbox use the bootstrap-shared `ExecutionGateway` and one
  `UniverseExecutionContextFactory`.
- Gate and production evaluation paths are async/cancellable; sync wrappers are
  restricted to callers outside an active event loop.
- Universe grants bind actor, correlation, contract, stage, argv, cwd, and the
  exact environment digest.
- Explicit literal environment values are restricted to a frozen non-secret
  Universe allowlist; secret-like names require opaque secret references and a
  resolver.  Evaluation keys are no longer embedded as literal env values.
- `secure-remote` requires attested strong sandboxing and never falls back to
  host.  `trusted-local` host execution is explicit and recorded as an advisory
  gap in Universe receipts.
- Sandbox start/health/timeout/cancel/stop/shutdown converge through
  `ExecutionHandle`, retain terminal receipts, reap process groups, and remove
  isolated databases.
- The unused container runner no longer launches directly or claims isolation;
  it remains an explicitly unavailable descriptor until a verified backend and
  image exist.
- The old host-only `code_variant_sandbox_mem_mb` claim was removed because no
  current backend can attest it.  Documentation now states the honest boundary.

## Independent review 1 — changes required

1. A normally exited leader can leave same-process-group descendants alive;
   `stop()` must converge the whole group without changing a completed success
   receipt.
2. DB cleanup errors currently remove the handle from retry tracking and can
   abort the rest of application shutdown.  Cleanup must be retryable and
   teardown must continue for MCP, bots, DrawerStore, and Storage.
3. `start()` racing `shutdown()` can create an active process after shutdown;
   add a closing barrier and track/cancel in-flight starts.
4. Remove SQLite main DB plus `-wal`/`-shm` sidecars, including failure paths.
5. Universe grant must bind resolved workspace/cwd/lease and stable complete
   principal identity, not only literal `.` and actor id.

   Gateway tool/MCP callers must not resolve that namespace.
7. Any ordinary backend spawn exception must be redacted and converted to a
   terminal start failure receipt; cancellation must still propagate.
8. Secure-remote pre-spawn sandbox denial must retain a terminal receipt in the
   exception and `SandboxRunner.last_receipt`.
9. Replace the long-lived `to_thread(_run_goal)` loop with a cancellable async
   polling path (or equivalently bounded cancellable design), so cancellation
   does not leave a polling thread running until goal timeout.
10. Remove the remaining misleading rlimit/memory/resource-isolation wording.

Add explicit RED tests for every item, report each RED reason and final focused
commands/results, then request re-review.

## Independent review 1 — fix wave

### RED evidence

1. Normal leader convergence: the new descendant fixture left its same-group
   child alive after `stop()` while the stored receipt remained `succeeded`.
2. Retryable cleanup: a one-shot `PermissionError` removed the handle from
   `_active`, so a second cleanup could not retry the database deletion; a
   failing sandbox teardown also skipped MCP, bots, DrawerStore, and Storage.
3. Closing barrier: a start blocked inside `ExecutionGateway.start()` completed
   after `shutdown()` returned and registered a new active process.
4. SQLite sidecars: stop and failed-start paths removed the main DB but left
   `-wal` and `-shm` files.
5. Grant scope: the Universe grant API had no workspace input and the same grant
   admitted a different workspace, lease, and same-id/different-kind Principal.
6. Secret namespace: governed tool and MCP requests resolved `settings:*`; the
   shared runtime resolver also fell unknown `settings:*` names through to the
   host environment.
7. Backend failures: a secret-bearing `RuntimeError` escaped unchanged without
   an `ExecutionStartError` receipt.
8. Secure preflight: `secure_remote_unavailable` returned
   `ExecutionDenied.receipt=None`, leaving `SandboxRunner.last_receipt` empty.
9. Eval cancellation: `_run_goal` was synchronous and dispatched as one
   long-lived `to_thread` polling loop; async fakes were never awaited and outer
   cancellation could not stop that worker loop.
10. Documentation truth: current design and ops documents still claimed memory
    rlimits, CPU/resource gates, or an isolated child process that the host
    backend does not enforce.

### GREEN implementation

- `SandboxRunner` now has a permanent closing barrier, tracks/cancels in-flight
  starts, converges the full process group even after a successful leader exit,
  retains cleanup failures for retry, and removes DB/WAL/SHM as one cleanup set.
  Application teardown logs a sandbox error and continues through later owners.
- Universe command grants sign a canonical complete-principal digest, workspace
  lease, and resolved workspace/cwd digests in addition to their existing exact
  stage/argv/environment/contract/correlation bindings.
- `settings:*` is denied before resolution outside governed Universe purposes;
  unknown runtime setting refs never fall through to the host environment.
- Ordinary backend exceptions become redacted terminal `ExecutionStartError`
  receipts, while cancellation remains cancellation. Pre-spawn denials now also
  carry terminal receipts, so secure-remote denial is retained by the runner.
- Eval goal submission/polling now uses cancellable `httpx.AsyncClient` requests
  and async sleeps with `trust_env=False` and redirects disabled.
- Current Universe design/ops/reference documents state the actual boundary:
  wall timeout, process-group convergence, independent DB cleanup, explicit
  trusted-local best effort, and secure-remote fail-closed without an attested
  backend.

## Independent review 2 — final fix wave

### RED evidence

- A backend created a real process, published its PID in the fixture, and then
  blocked before returning. Cancelling `SandboxRunner.start()` propagated a
  bare `CancelledError` with no receipt and left process ownership outside the
  Gateway. The fixture used events, not sleeps, and always killed its own process
  on RED failure.
- A backend publishing the same ownership twice produced a failed start receipt
  but left the real process alive.
- Secure-remote Gate denial escaped `Gate.run_async()` and left
  `Gate.last_receipts` empty.
- The eval fake clock advanced exactly to the goal deadline during sleep, but
  polling still issued one GET using stale pre-sleep remaining time.
- Ops/implementation/current design docs still used an enforced-memory or
  strongly isolated-process framing and did not all state the trusted-local
  boundary.

### GREEN implementation

- `ProcessBackend` now has an explicit exactly-once ownership handoff callback.
  The built-in backend shields low-level acquisition, publishes immediately
  after process creation and before any later await, and preserves cancellation.
  Gateway cancellation settles the backend task, terminates every published
  process group, and re-raises `ExecutionStartCancelled` (an
  `asyncio.CancelledError`) with a terminal cancelled receipt. Duplicate or
  mismatched publication fails closed and all published PIDs are reaped.
- `SandboxRunner` retains a cancellation receipt while preserving the caller's
  cancellation semantics.
- Gate converts receipt-bearing `ExecutionDenied` into the same failed
  `GateResult` shape as startup failure and retains the receipt.
- Eval polling recomputes remaining time after sleep and does not send a request
  at or beyond the deadline.
- Current docs now describe an independent DB path, wall timeout, process-group
  convergence and trusted-local best effort rather than memory/strong-sandbox
  enforcement.
