## Delivered scope

- Added immutable, extra-forbid execution models: `ExecutionRequest`, `ExecutionResult`,
  `ExecutionReceipt`, `EnvironmentPolicy`, `NetworkPolicy`, `SandboxRequirement`,
  `ArgvCommand`, and `ShellCommand`.
- Added one async `ExecutionGateway.run()` / `start()` boundary backed by the sole low-level
  `asyncio.create_subprocess_exec` launcher.
- Added fail-closed identity/effective-contract, command, cwd/symlink, env/secret, timeout,
  sandbox, and network guards; mandatory guard error/timeout denies, while advisory abstention
  creates a structured gap.
- Restrictive network policies now require an enforcing backend before spawn. The backend receives
  the resolved network/sandbox policies and must return enforcement proof, which is persisted in
  the receipt with the backend identity.
- Required sandbox requests also require per-process proof after spawn. A backend-level capability
  claim is insufficient: missing/false proof terminates and reaps the process before returning a
  structured denial, including the Darwin process-group probe race observed during verification.
- Command grants are short-lived, HMAC-signed, run/contract-bound authority records. Shell grants
  derive from frozen effective prefixes or an explicit PolicyHook authorization; acceptance grants
  derive from the frozen check; Lark and Keqing grants are purpose-limited. Keqing additionally
  reuses adapter-owned canonical executable/headless-argv validation at issue and execution time.
- Added concurrent bounded stdout/stderr draining, streaming stdout, byte truncation receipts,
  one start-to-finish deadline, timeout/cancellation process-group cleanup even after the leader
  exits, exit/signal distinction, and explicit secret-value redaction (including values split
  across pipe reads).
- Migrated only the G1.3a callers: built-in `shell_exec`, outer-loop bash/lint acceptance checks,
  `lark_cli`, and Keqing Claude/Codex CLI.
- Bound the G1.2 prepared effective contract and persisted submitter reference into a run-local
  `ExecutionContext`; bootstrap creates one gateway and injects it into tools, Executor/Keqing,
  and the outer-loop context.
- Keqing remains `contained + experimental`; its opaque tool events remain observed and its
  gateway receipt is additive in `AgentResult.events`, including the budget-exhaustion terminal
  path after cancellation cleanup.
- Did not migrate MCP, Universe, Git, LSP, grep, eval, or lifecycle `os.exec*`; no WorkspaceService,
  durable journal, or Native managed claim was added.

## Truthful limits / concerns

- Host execution is not a strong sandbox and cannot enforce deny/allowlist networking. A required
  sandbox or `secure-remote` request fails closed, and any restrictive network request now also
  fails closed unless the selected backend supplies enforcement and returns proof.
- Process-group cleanup is verified on this macOS/POSIX host. Windows tree cleanup is not proven;
  the fallback terminates the direct process only.
- Secret refs currently resolve from named environment variables. This is a reference/value split,
  but not yet a mount/keychain/secret-service backend. Exact-value streaming redaction covers only
  values successfully resolved by the gateway, plus the existing generic outbound patterns.
- The supplied workspace root is still the current validated root/legacy lease placeholder. There
  is no per-run staging, restore point, governed apply, or strong workspace isolation until G1.4.
- Keqing action interception remains unsupported; JSONL tool events are observations, not proof of
  per-action authorization.
- G1.3b process launch inventory remains intentionally present outside the four migrated callers.
- G2 durable/exactly-once side-effect journaling is not implemented; receipts are in-memory/additive
  evidence, not a durable journal.
