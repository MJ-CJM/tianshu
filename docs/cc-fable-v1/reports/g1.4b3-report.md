## 2. 收口期间发现并修复的缺陷（TDD）

### 2.1 Pre-ledger 恢复路径被 V5 破坏（10 个测试失败的共同根因）

- **现象**：17 文件 owned suite 首跑 10 failed——全部为
  `migration 4 (0004_workspace_foundation) failed`。
- **根因**：已冻结的 V4 采纳校验 `_validate_workspace_foundation_schema` 用
  "精确匹配 V4 reference 形状"接受已存在表。该语义隐含"V4 是最后一个
  workspace 迁移"的潜在假设；WIP 新增的 V5（给 `apply_decisions` 加 8 个
  绑定列、替换不可变触发器）使"丢失 ledger 的最新形状库"在 V4 处被
  fail-closed 拒绝。STATUS 披露的"V4 callback 曾被改写"即为此问题的
  被撤销错误修法（触碰冻结迁移）。
- **裁决与修复（canonical adopt）**：不动任何冻结迁移。框架层新增：
  pre-ledger 库若与"全部迁移完成后的权威形状"语义等价（owned 表签名
  列序不敏感比对 + 命名索引 + 触发器全比对，FTS 触发器按 V1 的
  `_EXPECTED_OPTIONAL_TRIGGERS` 精确豁免；额外用户表忽略；残留迁移
  临时表拒绝），则 `adopt_migrations` 单事务整体采纳只补 ledger；
  否则逐版重放（V4 永远只遇到 ≤V4 形状，冻结语义依然成立）。对未来
  V6+ 自动成立。
- **附带修正**：historical fixtures 失真（真实历史库不含 workspace 表）；
  新增守卫测试 `test_v4_shape_preledger_replays_v5_instead_of_adopt`
  锁定"半新库不被 adopt 误吞、逐版重放仍工作"。
- **证据**：RED 10 failed → GREEN storage 域 124 passed、17 文件 suite
  344 passed / 2 skipped / 0 failed。

### 2.2 迁移 callback 可被无声改写（P1 复审 CRITICAL）

- **根因**：migration checksum 只覆盖 SQL 语句文本，upgrade/validate
  callback 的 Python 源码不入指纹——V4 事件正是踩中此缺口。
- **修复**：新增 `tests/storage/test_migration_callback_freeze.py`，冻结
  全部 5 个 upgrade callback + 2 个 validate helper + canonical adopt
  门控（`_matches_canonical_schema`、`adopt_migrations`，采纳独立审查
  MINOR#1）的源码 SHA-256。变异验证：V4 callback 插入一行 → 精确命中
  该条目变红；恢复 → 全绿。正式修订路径：先在 PROGRESS.md 记录裁决再
  更新指纹。

### 2.3 STATUS 五项暂停前修复的落地确认（独立审查逐项核验，全部实跑绿）

1. POSIX mode 漂移 fail-closed：`_desired_posix_mode` + `verify_materialized`；
   0600→0640 触发 `rollback_failed + CLEANUP_FAILED`，非成功 receipt。
2. authority expiry/active lease 原子 claim：version CAS + V5
   `validate_apply_decision_state` 触发器强制 consumed 时
   `created_at < expires_at` 且 latest lease_state=active。
3. `close_lease` 取 source+process 锁，pending 未过期拒绝关闭，
   `has_unreceipted_apply_claim_for_lease` 堵 host-crash 间隙。
4. V4 callback 改写已撤销（diff 零触碰 + 指纹冻结），V5 纯 additive
   （`test_frozen_v4_callback_rejects_v5_schema_without_v4_ledger`）。
5. rollback 真值：`rollback_status="succeeded"` 仅在实际 engine.restore
   成功后设置；6 阶段故障注入矩阵锁定。
