# ADR-0012:治理动作统一为「裁决」

- 状态:已接受
- 日期:2026-07-11
- 相关:[ADR-0008](0008-court-deliberation-censor-structured-stance.md)(廷议)、[ADR-0011](0011-keqing-external-executor-shadow-snapshot.md)(客卿治理边界)

## 背景

界面此前混用「批红」「朱批」「审批」等词。其中「批红」和「朱批」带有明确的
明代司礼监制度语境，容易把治理权误解为特定历史角色的职权；「审批」又会与
质量审阅、审计复核混在一起。天枢的治理动作可能由人、策略或自动化规则作出，
需要一个不绑定执行者、同时能表达允许、拒绝、重试、修订和撤销的总称。

## 决策

### 1. 用户可见的治理总称使用「裁决」

中文界面统一使用「裁决」「待裁决」「裁决中心」「裁决授予」等表达。允许执行
仍可使用「准」「批准」或「放行」，它们是裁决结果，不是治理流程的名称。

英文治理界面使用 `Decision`、`Pending Decision` 和 `Decide`；具体结果使用
`Allow` / `Reject`。英文中的 `Review` 仅保留给质量审阅、监督报告和评测策略。

### 2. 质量审阅术语保持独立

critic、supervision、audit 等质量判断继续使用「审阅」「审核」「复核」和
`Review`。这些动作评价执行质量，不代表是否授权工具调用或任务继续执行。

### 3. 保持协议与存量数据兼容

本次只修改用户可见文案，不重命名既有 locale key、事件名、API 字段或存储值。
例如 `nav.approvals`、`status.needs_review`、`decree.*`、
`tool.approval_required` 继续保留。历史 ADR 和已落盘事件作为事实记录不做追溯
改写；新界面和后续文档遵循本 ADR。

### 4. 用自动化契约防止术语回退

三套 locale 必须保持完全一致的 key 结构。中文用户可见值不得重新出现旧治理
称谓；英文治理专用 key 由精确映射约束，同时显式保留质量 `Review` 语义和内部
兼容标识。

## 影响

- 产品叙事从历史角色代办转为可由多种主体执行的治理裁决。
- 允许、拒绝、重试、修订和撤销仍沿用现有内部事件与 API，不产生迁移成本。
- 新增 locale 术语契约测试；新增或修改文案时须同时更新三套 locale。
