# DAG 维持静态展开,明确拒绝动态图

未来读者(或热心贡献者)会觉得"执行中能生长的动态图"(LangGraph 式)更强大,想来"修复"静态 DAG。这是深思熟虑的拒绝,不是能力欠缺:天枢的 DAG 由 Plan 静态展开(`depends_on` 依赖),**图先于执行存在**——这是治理链成立的前提:票拟预审要有完整的图可审、六科封驳要有完整的图可估、级联取消要有确定的边界可取消。动态图=计划不可预审,与"大事慎决"的治理叙事根本冲突。执行中产生的新需求已有两条归宿:orchestrator 外环迭代(验收不过自动再规划)与 follow-up 机制(runtime_override 单轮覆盖)。市场亦佐证:生产系统已收敛到 orchestrator-worker(约七成),swarm/动态 handoff 因成本与不可控退潮。
